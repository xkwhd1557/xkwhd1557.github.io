3.1 셸과 배쉬 시작하기

3장 재현 가능한 작업 환경 · 가장 가볍게 데이터에 닿는 방법

데이터 사이언스·AI
데이터 사이언스 개론
큰 데이터를 다룰 때 셸이 왜 필요한지 살펴보고, 유닉스 셸과 배쉬가 무엇인지 소개합니다. 윈도우, 맥, 리눅스, 안드로이드(Termux)별로 배쉬를 설치하고, 프로젝트 폴더로 이동하는 법과 주피터 노트북에서 배쉬를 쓰는 법을 정리합니다.
Published

November 4, 2026

들어가며

2장에서는 데이터를 숫자와 그림으로 요약하는 방법을 파이썬으로 살펴보았습니다. 그런데 실제 데이터 탐색은 파이썬보다 한 단계 앞에서 시작되는 경우가 많습니다. 이번 글에서는 그 첫 단계에서 쓰는 도구인 셸(shell)과 배쉬(Bash)를 소개하고, 각자의 컴퓨터에서 배쉬를 쓸 수 있도록 준비해 보겠습니다.

엑셀로도, 파이썬으로도 열리지 않는 파일

1.1에서 빅데이터의 3V 가운데 크기(volume)를 이야기했습니다. 거기서 언급됐던 케이스들은 극단적으로 크기가 큰 케이스들이긴 했는데요, 그렇게까지 가지 않더라도 이 크기의 벽은 생각보다 가까이서 찾아볼 수 있습니다. 예를 들어 CSV 파일(대충 엑셀같이 표 형태의 파일)을 분석해야 한다고 해 보겠습니다. 지금의 여러분들이라면 우선 이 엑셀 파일을 여는거부터 시작하실겁니다. 당연하죠. 일단 데이터를 확인해야하니까요. 근데 사실 이거부터가 불가능합니다.

보통 지금까지 다루신 엑셀 파일들은 해봤자 키로바이트 수준의 매우 작은 크기의 파일들일겁니다. 그래서 지금까지는 어떤 엑셀 파일을 오픈하더라도 그냥 길어도 10초 기다리면 딱 파일을 확인할 수 있으셨을거에요. 하지만 이 엑셀의 크기가 메가 단위가 되고, 더 넘어가 기가 단위가 되면 오픈하는거 자체가 불가능할 가능성이 높습니다. 만약 직접 시도하신다면 운이 좋은 경우에도 수십분이 걸리는건 기본이고, 십중팔구 정상적으로 열리지 않거나, 컴퓨터가 다운될겁니다. 신기하죠. 아마 지금까지 이런 파일을 열 일이 없으셔 모르셨을거에요. 심지어 이 파일을 (지금 우리가 아는 방법으로) 파이썬의 판다스로 읽으려 해도, 파일 전체를 메모리에 올리려다 메모리가 부족해 오류가 날 것입니다.

직접 해 보기(안하셔도 됩니다.)

말로만 들으면 와닿지 않으니 직접 해 보셔도 좋습니다. 미국 시카고시는 2001년부터 지금까지 시카고 경찰에 신고된 범죄 사건 기록을 공개 데이터 포털에서 누구나 내려받을 수 있게 공개하고 있습니다.1 매일 갱신되며 수백만 건이 쌓인 데이터라, CSV 파일 하나가 GB 단위입니다. 데이터 페이지에서 Export → CSV → Download를 누르시면 바로 내려받을 수 있습니다. 용량이 커서 내려받는 데만 꽤 걸리고, 디스크 공간도 몇 GB 정도 비워 두는 것이 좋습니다.

만약 지금 작성중이거나 뭔가 저장해야 할 문서가 있으면 일단 저장을 끝낸 후, 받은 파일을 엑셀로 열어 보세요. 아마 보통 가정용 PC에서는 그냥 컴터가 다운되거나 거의 수십분이 걸릴겁니다. 한참을 기다린 끝에 파일을 열면 “파일을 완전히 로드하지 못했습니다” 같은 경고가 뜨고, 앞부분만 불러와집니다. 엑셀의 시트 한 장에는 1,048,576행까지만 들어가는데, 이 데이터는 그보다 몇 배나 많기 때문입니다.2 화면에 보이는 것이 데이터의 일부일 뿐이라는 것을 모르고 그대로 분석했다면, 전체 데이터가 아니라 잘려 나간 앞부분만으로 결론을 내리게 됩니다. 반면 다음 글과 3.4에서 볼 배쉬 명령어를 쓰면, 이 파일의 앞 10줄을 보는 데는(head) 눈 깜짝할 시간밖에 걸리지 않고, 전체가 몇 줄인지 세는 것도(wc -l) 금방 끝납니다.

이런 일이 생기는 것은, 엑셀이나 메모장처럼 우리가 평소에 쓰는 프로그램들이 사용자에게 편리한 화면을 보여 주기 위해 파일 전체를 한꺼번에 불러오기 때문입니다. 데이터 분석가들은 이 편리함을 포기하는 대신, 훨씬 가볍게 데이터에 접근하는 도구를 씁니다. 그것이 바로 셸과 배쉬입니다. 배쉬를 쓰면 수천만 줄짜리 파일에서 맨 앞 10줄만 바로 뽑아 보거나, 전체가 몇 줄인지 순식간에 세거나, 특정 단어가 들어간 줄만 골라내는 일을 파일 전체를 열지 않고도 할 수 있습니다. 데이터의 포장을 가장 원초적이고 빠른 방식으로 뜯어서 만져볼 수 있는거죠.

그래서 데이터 탐색은 2장에서 본 것처럼 파이썬이나 R로 데이터를 바로 가져가서 진행되진 않고, 우선 셸로 데이터를 1차로 훑고 걸러 낸 다음 다루기 좋은 크기와 모양으로 만드는거부터 출발합니다. 3.1부터 3.4까지는 이 첫 단계를 다룹니다.

셸이란 무엇일까요?

유닉스 셸(Unix shell), 줄여서 셸은 유닉스라는 오래된 운영체제와 그 전통을 잇는 운영체제들(리눅스, 맥OS 등)에서 쓰는 명령줄 인터프리터(command-line interpreter)입니다. 해커나 프로그래머를 떠올리면 생각나는, 검은 화면에 알 수 없는 명령어를 입력하는 바로 그것입니다.

말은 어렵지만, 명령줄 인터프리터는 사람이 글자로 입력한 명령을 운영체제가 알아듣게 전달해 주는 도구입니다. C나 파이썬 같은 프로그래밍 언어와는 쓰임새가 조금 다릅니다. 프로그래밍 언어는 새로운 프로그램을 만드는 데 쓰는 반면, 셸은 이미 있는 프로그램이나 파일을 관리하고 다루는 데 씁니다. 우리는 폴더를 더블클릭해서 열고 파일을 끌어다 옮기는 그래픽 화면(GUI)에 익숙하지만, 그런 화면이 없던 시절에는 이 모든 일을 명령어로 했고, 셸은 그 방식이 지금까지 이어진 것입니다. 리눅스나 맥에서 터미널(terminal)을 열면 나오는 화면이 바로 셸입니다.

윈도우에는 유닉스 셸은 아니지만 파워셸(PowerShell)이라는 비슷한 도구가 있습니다. 하지만 전 세계의 서버와 클라우드 환경은 대부분 리눅스로 돌아가기 때문에, 윈도우 사용자도 파워셸 대신 깃 배쉬(Git Bash)나 WSL(Windows Subsystem for Linux)을 설치해서 유닉스 셸 환경에서 작업하는 경우가 많습니다. 설치 방법은 아래에서 운영체제별로 정리하겠습니다.

대화형이자 스크립트

셸은 두 가지 방식으로 씁니다.

  • 대화형(interactive): 컴퓨터와 1:1로 채팅하듯 명령어를 하나 입력하고 결과를 보고, 또 하나 입력하고 결과를 봅니다. 예를 들어 ls를 입력하면 컴퓨터가 지금 폴더의 파일 목록을 보여 줍니다.
  • 스크립트(script): 이렇게 매번 하나씩 입력하는 대신, 여러 명령어를 텍스트 파일에 차례로 적어 두고 한 번에 실행합니다. 이것을 셸 스크립팅(shell scripting)이라고 하고, 3.3에서 다룹니다.

셸을 다 외울 필요는 없습니다

셸은 아주 방대합니다. 명령어도 엄청나게 많고, 명령어 하나에 붙는 옵션도 많으며, 기호와 순서가 직관적이지 않아서 셸을 완전히 자유자재로 쓰는 것은 거의 불가능합니다. 경력이 많은 개발자도 검색해서 찾은 명령어를 복사해 쓰는 일이 흔합니다.

셸 사용자들 사이에서 유명한 xkcd 만화가 있습니다.3 폭탄을 해체하려면 유닉스를 쓰는 동료 롭이 tar라는 명령어를 검색 없이 10초 안에 올바르게 입력해야 하는데, 결국 롭이 “정말 미안해”라고 말하며 포기하는 내용입니다. 이 만화가 웃긴 이유는, tar가 사실 대단한 명령어가 아니라는 데 있습니다. tar는 파일 여러 개를 하나로 묶거나 묶음을 푸는 아주 흔한 명령어입니다. 다만 옵션 글자의 순서와 의미가 워낙 헷갈려서, 매일 쓰는 사람도 막상 외워서 치라고 하면 자신이 없는 것이지요. 참고로 tar는 대략 이런 모양입니다.

tar -xzvf archive.tar.gz

그러니 중요한 것은 셸을 마스터하는 것이 아니라, 우리 목적에 필요한 핵심 명령어 몇 개가 무엇을 하는지 익히고, 언제 어떤 명령어가 필요한지 감을 잡는 것입니다. 세세한 옵션은 그때그때 검색하거나 AI에게 물어보면 됩니다.

셸과 배쉬

그런데 사실 우리가 공부할 것은 셸 전체가 아니라 배쉬입니다. 셸은 일종의 분류 이름입니다. “스마트폰”이라는 분류 안에 여러 회사의 제품이 있듯이, 셸이라는 분류 안에는 배쉬, zsh, fish 같은 여러 셸이 있습니다. 그중 배쉬는 대부분의 리눅스 배포판에서 기본 셸로 쓰이고, 클라우드 서버에서도 가장 흔히 만나는 셸이라 사실상 표준처럼 쓰입니다. 그래서 이 과목에서도 배쉬를 기준으로 데이터를 다루는 법을 설명합니다.

배쉬 설치하기

이제 각자의 컴퓨터에서 배쉬를 쓸 수 있게 준비해 보겠습니다. 아래에서 자기 운영체제의 탭을 골라 보시면 됩니다. 한 번 고른 운영체제는 이 페이지의 다른 탭에도 똑같이 적용됩니다.

  • Windows
  • macOS
  • Linux
  • Android (Termux)

윈도우에서는 깃 배쉬(Git Bash)를 설치하는 것이 가장 간단합니다. 깃 배쉬는 3.7에서 다룰 버전 관리 도구 깃(Git)을 설치하면 함께 따라오는 배쉬 환경입니다.

  1. git-scm.com에서 윈도우용 설치 파일을 내려받아 실행합니다.
  2. 설치 도중 나오는 여러 선택지는 잘 모르겠으면 건드리지 않고 기본값으로 넘기면 됩니다.
  3. 마지막 화면에서 Launch Git Bash에 체크하고 마치면, 검은 배쉬 창이 열립니다. 다음부터는 시작 메뉴에서 “Git Bash”를 검색해서 열면 됩니다.

깃 배쉬는 가볍고 편리하지만, 진짜 리눅스는 아니라서 몇몇 리눅스 프로그램은 쓸 수 없습니다. 아래에서 설명할 주피터 노트북의 배쉬 커널처럼 진짜 리눅스 환경이 필요할 때는 WSL을 쓰면 됩니다. WSL은 윈도우 안에서 진짜 리눅스(기본값은 우분투)를 돌려 주는 기능으로, 관리자 권한으로 연 파워셸에서 다음 한 줄을 입력하고 컴퓨터를 다시 시작하면 설치됩니다.4

wsl --install

다시 시작한 뒤 시작 메뉴에서 “Ubuntu”를 열면, 처음 한 번 사용자 이름과 비밀번호를 정하라고 나오고, 그다음부터는 우분투의 배쉬를 그대로 쓸 수 있습니다.

맥에는 셸이 이미 들어 있으니 따로 설치할 것이 없습니다. 터미널(Terminal) 앱을 열면 됩니다. Spotlight(⌘ + Space)에서 “터미널”을 검색하거나, Finder의 응용 프로그램 → 유틸리티 폴더에서 찾을 수 있습니다.

다만 한 가지 알아 둘 점이 있습니다. 맥OS 카탈리나(10.15)부터는 터미널의 기본 셸이 배쉬가 아니라 zsh입니다. zsh는 배쉬와 아주 비슷해서 이 과목의 명령어 대부분이 그대로 동작하지만, 배쉬로 실습하고 싶다면 터미널에서 다음을 입력하면 됩니다.

bash

맥에 기본으로 들어 있는 배쉬는 라이선스 문제로 2007년에 나온 3.2 버전에 머물러 있습니다. 이 과목의 내용은 3.2로도 충분하지만, 최신 배쉬가 필요하다면 패키지 관리자인 Homebrew를 설치한 뒤 brew install bash로 설치할 수 있습니다.

리눅스는 대부분의 배포판에서 배쉬가 기본 셸이라 따로 설치할 것이 없습니다. 터미널을 열면 바로 배쉬입니다. 우분투에서는 Ctrl + Alt + T를 누르거나, 프로그램 목록에서 “터미널”을 찾으면 됩니다.

지금 쓰고 있는 셸이 배쉬인지 확인하려면 다음을 입력해 보세요. /bin/bash처럼 bash로 끝나는 경로가 나오면 배쉬입니다.

echo $SHELL

termux-setup-storage

첫 명령어: 지금 어디에 있나요?

배쉬 창을 열었다면, 먼저 내가 지금 어느 폴더에 있는지부터 확인해 보겠습니다. 셸은 언제나 어떤 한 폴더를 “바라보고” 있는데, 이 폴더를 작업 디렉터리(working directory)라고 합니다. 디렉터리(directory)는 폴더를 뜻하는 말입니다.

pwd(print working directory)는 지금 작업 디렉터리의 경로를 보여 줍니다.

pwd
/home/user

셸을 처음 열면 보통 사용자의 홈 디렉터리(home directory)에서 시작합니다. 여기서는 사용자 이름이 user라서 /home/user가 나왔고, 각자의 화면에서는 각자의 경로가 나옵니다. 홈 디렉터리는 줄여서 ~(물결표)로 쓰기도 합니다.

ls(list)는 지금 폴더에 무엇이 있는지 보여 줍니다.

ls
Documents  project

cd(change directory)는 다른 폴더로 옮겨 갑니다. project 폴더로 들어가서 다시 확인해 보겠습니다.

cd project
pwd
ls
/home/user/project
README.md  analysis.py  data

경로를 쓸 때 쓰는 몇 가지 약속이 있습니다.

  • .은 지금 폴더, ..은 한 단계 위의 폴더입니다. cd ..이면 한 단계 위로 올라갑니다.
  • ~는 홈 디렉터리입니다. 어디에 있든 cd ~ 또는 그냥 cd라고만 치면 홈으로 돌아갑니다.
  • /로 시작하는 경로는 컴퓨터의 맨 꼭대기(루트)부터 적은 절대 경로이고, 그렇지 않은 경로는 지금 폴더를 기준으로 적은 상대 경로입니다.
cd ..
pwd
cd project/data
pwd
cd ~
pwd
/home/user
/home/user/project/data
/home/user

내 프로젝트 폴더로 가기

실습을 하려면 셸이 내 데이터나 코드가 있는 폴더를 바라보게 해야 합니다. 방법은 운영체제마다 조금씩 다릅니다.

  • Windows
  • macOS
  • Linux
  • Android (Termux)

깃 배쉬에서는 윈도우의 드라이브가 /c, /d처럼 보이고, 경로 구분 기호도 \ 대신 /를 씁니다. 예를 들어 윈도우 탐색기의 C:\Users\ParkJongWoo\Documents\project는 깃 배쉬에서 다음과 같이 씁니다.

cd /c/Users/ParkJongWoo/Documents/project

더 편한 방법도 있습니다. 탐색기에서 프로젝트 폴더를 열고, 빈 곳을 마우스 오른쪽 버튼으로 누른 뒤 Open Git Bash here를 고르면, 그 폴더를 바라보는 깃 배쉬가 바로 열립니다. (윈도우 11에서는 오른쪽 클릭 메뉴의 “추가 옵션 표시” 안에 있습니다.)

WSL의 우분투에서는 윈도우의 C 드라이브가 /mnt/c에 있습니다. 위의 폴더라면 cd /mnt/c/Users/ParkJongWoo/Documents/project가 됩니다.

맥의 홈 폴더는 /Users/사용자이름이고, ~로 줄여 쓸 수 있습니다. 예를 들어 문서 폴더 안의 project 폴더라면 다음과 같습니다.

cd ~/Documents/project

경로를 직접 치기 번거롭다면, 터미널에 cd(cd 뒤에 공백 하나)까지만 입력한 다음 Finder에서 폴더를 터미널 창으로 끌어다 놓으면 경로가 자동으로 입력됩니다. 엔터만 누르면 됩니다.

리눅스의 홈 폴더는 보통 /home/사용자이름이고, ~로 줄여 쓸 수 있습니다.

cd ~/Documents/project

우분투의 파일 관리자에서는 폴더 빈 곳을 마우스 오른쪽 버튼으로 누르고 터미널에서 열기를 고르면, 그 폴더를 바라보는 터미널이 열립니다.

Termux의 홈 디렉터리는 앱 전용 공간이라, 휴대폰의 다른 앱에서는 보이지 않습니다. 위에서 termux-setup-storage를 실행했다면, 내부 저장소의 다운로드 폴더는 다음 경로로 갈 수 있습니다.

cd ~/storage/downloads

다만 내부 저장소에서는 파일 권한 설정 같은 일부 기능이 제한되기 때문에, 실습할 때는 파일을 Termux 홈으로 복사해 와서 작업하는 편이 편합니다. 예를 들어 다운로드 폴더의 data.csv를 홈의 project 폴더로 복사하려면 mkdir -p ~/project && cp ~/storage/downloads/data.csv ~/project/처럼 합니다.

주피터 노트북에서 배쉬 쓰기

배쉬는 지금 연 배쉬 창에 명령어를 하나씩 입력하며 써도 충분합니다. 다만 3.5에서 이야기할 것처럼, 코드와 설명과 결과를 한 문서에 함께 남겨 두면 나중에 다시 보거나 다른 사람에게 보여 주기 훨씬 좋습니다. 주피터 노트북(Jupyter Notebook)은 원래 파이썬용으로 많이 쓰지만, 배쉬 커널(bash kernel)을 설치하면 노트북의 코드 셀에 배쉬 명령어를 적고 실행할 수 있습니다.

  • Windows
  • macOS
  • Linux
  • Android (Termux)

아쉽게도 배쉬 커널은 윈도우에서 직접은 동작하지 않습니다. 배쉬 커널이 내부적으로 쓰는 pexpect라는 라이브러리의 핵심 기능이 유닉스 계열 운영체제에만 있는 기능에 의존하기 때문입니다.6 그래서 윈도우에서는 위에서 설치한 WSL의 우분투 안에 주피터를 설치해서 씁니다. 우분투를 열고 다음을 차례로 입력합니다.

sudo apt update
sudo apt install -y python3-pip python3-venv
python3 -m venv ~/jupyter-env
source ~/jupyter-env/bin/activate
pip install jupyter bash_kernel
python -m bash_kernel.install
jupyter lab

세 번째와 네 번째 줄은 주피터를 위한 가상 환경을 만들고 켜는 명령어인데, 무엇인지는 3.9에서 자세히 다룹니다. 마지막 줄을 실행하면 http://localhost:8888/lab?token=... 같은 주소가 나옵니다. 이 주소를 윈도우의 웹 브라우저에 붙여 넣으면 주피터가 열립니다. 다음에 다시 쓸 때는 우분투에서 source ~/jupyter-env/bin/activate와 jupyter lab 두 줄만 입력하면 됩니다.

터미널에서 다음을 차례로 입력합니다.

python3 -m venv ~/jupyter-env
source ~/jupyter-env/bin/activate
pip install jupyter bash_kernel
python -m bash_kernel.install
jupyter lab

첫 두 줄은 주피터를 위한 가상 환경을 만들고 켜는 명령어인데, 무엇인지는 3.9에서 자세히 다룹니다. 마지막 줄을 실행하면 웹 브라우저에서 주피터가 열립니다. 다음에 다시 쓸 때는 source ~/jupyter-env/bin/activate와 jupyter lab 두 줄만 입력하면 됩니다.

파이썬과 주피터를 한 번에 설치해 주는 아나콘다(Anaconda)를 이미 쓰고 계신다면, 아나콘다 환경에서 pip install bash_kernel과 python -m bash_kernel.install 두 줄만 실행해도 됩니다.

터미널에서 다음을 차례로 입력합니다. (우분투라면 먼저 sudo apt install -y python3-pip python3-venv로 필요한 패키지를 설치해 두세요.)

python3 -m venv ~/jupyter-env
source ~/jupyter-env/bin/activate
pip install jupyter bash_kernel
python -m bash_kernel.install
jupyter lab

첫 두 줄은 주피터를 위한 가상 환경을 만들고 켜는 명령어인데, 무엇인지는 3.9에서 자세히 다룹니다. 마지막 줄을 실행하면 웹 브라우저에서 주피터가 열립니다. 다음에 다시 쓸 때는 source ~/jupyter-env/bin/activate와 jupyter lab 두 줄만 입력하면 됩니다.

Termux에도 파이썬을 설치하고 주피터를 올릴 수는 있지만, 설치할 것이 많고 스마트폰에서는 무겁습니다. Termux에서는 주피터 없이 배쉬 창에서 바로 실습하시기를 권합니다. 이 과목의 배쉬 예제는 모두 배쉬 창에서 그대로 따라 할 수 있습니다.

주피터가 열리면 오른쪽 위의 New(주피터 랩에서는 런처 화면)를 눌렀을 때 Bash라는 선택지가 새로 생긴 것을 볼 수 있습니다. 이것으로 노트북을 만들면, 코드 셀에 적은 내용이 모두 파이썬이 아니라 배쉬 명령어로 실행됩니다.

한 가지 팁을 덧붙이면, 주피터를 켰을 때 브라우저가 자동으로 열리지 않거나 “접근이 거부되었습니다” 같은 오류가 나는 경우가 있습니다. 이때는 터미널에 출력된 주소들 가운데 file://로 시작하는 주소 대신, http://localhost:8888/... 또는 http://127.0.0.1:8888/...로 시작하는 주소를 통째로 복사해서 브라우저 주소창에 붙여 넣으면 대부분 해결됩니다.

정리

  • 아주 큰 데이터는 엑셀이나 파이썬으로 바로 열기 어렵기 때문에, 먼저 셸로 가볍게 훑고 걸러 내는 것이 데이터 탐색의 첫 단계입니다.
  • 셸은 글자로 입력한 명령을 운영체제에 전달하는 명령줄 인터프리터이고, 배쉬는 그중 가장 널리 쓰이는 셸입니다.
  • 윈도우는 깃 배쉬나 WSL, 맥과 리눅스는 기본 터미널, 안드로이드는 Termux로 배쉬를 쓸 수 있습니다.
  • pwd로 지금 위치를, ls로 폴더 내용을, cd로 폴더 이동을 합니다. .은 지금 폴더, ..은 위 폴더, ~는 홈입니다.

준비가 끝났으니, 다음 글에서는 배쉬의 기본 명령어와, 명령어들을 연결하는 파이프를 본격적으로 다뤄 보겠습니다.
