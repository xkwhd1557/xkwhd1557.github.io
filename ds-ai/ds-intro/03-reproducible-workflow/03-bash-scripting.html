3.3 배쉬 스크립팅

3장 재현 가능한 작업 환경 · 명령어를 프로그램처럼 엮기

데이터 사이언스·AI
데이터 사이언스 개론
배쉬의 변수, 따옴표, 명령어 치환, 환경 변수, 조건문과 종료 코드, 반복문, 표준 입력·출력·에러 스트림을 정리하고, 명령어들을 .sh 스크립트 파일로 저장해 실행하는 법을 운영체제별로 살펴봅니다.
Published

November 4, 2026

들어가며

지난 글에서는 배쉬 명령어를 하나씩 입력하고, 파이프로 이어 붙여 보았습니다. 3.1에서 말했듯이 배쉬는 대화형으로 쓸 수도 있지만, 여러 명령어를 미리 파일에 적어 두고 한 번에 실행하는 스크립트(script)로도 쓸 수 있습니다.

지난 포스팅에서 요즘에는 AI에게 “이런 작업을 하는 배쉬 스크립트를 짜 줘”라고 하면 순식간에 코드를 만들어 주기 때문에, 배쉬를 몰라도 그리 큰 문제는 없을거처럼 얘기를 했는데요, 스크립팅의 이야기로 넘어가면 조금 달라집니다. 배쉬를 통해 단편적인 명령을 수행하는 경우라면 걍 챗지피티 해줘! 하면 되지만, 우리는 가끔 그 명령을 다시 실행할 경우를 위해 이를 하나의 스크립트로 남겨두는 경우가 있습니다. 이 때는 본인이 그 스크립트가 어떤 방식으로 어떤 작용을 하는지 이해하는 게 필요한 경우들이 많습니다. 지금 당장 쓰고 치우는 게 아니라, 계속 쓸 친구다보니 오류가 있으면 잡아내야 하며, 프로젝트 수정 과정에서 고칠 점이 있으면 고쳐야 하거든요. 그래서 배쉬 스크립팅의 기초 문법 정도는 알고 있어야 합니다. 물론 이거도 LLM이 다 가능하긴합니다..

스크립팅은 C, 자바, 파이썬으로 프로그래밍을 하는 것과 크게 다르지 않습니다. 차이가 있다면, (여러 번 언급했지만) C나 자바, 파이썬은 우리가 세운 알고리즘을 수행하는 새 프로그램을 만드는 데 쓰는 반면, 배쉬 스크립팅은 이미 컴퓨터에 있는 프로그램과 데이터 파일을 조작하는 과정을 미리 짜 두고 빠르게 실행하는 데 쓴다는 점입니다. 이제 스크립트를 이루는 요소들을 하나씩 살펴보겠습니다.

변수

프로그래밍에서 가장 기본이 되는 단위는 변수(variable)입니다. 보통 변수는 자료형에 따라 성질이 달라지지만, 지난 글에서 보았듯이 배쉬의 변수는 언제나 문자열이라서 복잡할 것이 없습니다. 변수는 다음과 같이 만듭니다.

player="Ralo"

다른 프로그래밍 언어처럼 =의 왼쪽에는 변수의 이름을, 오른쪽에는 변수에 넣을 값을 적습니다. 여기서 주의할 점은 =의 양옆에 공백이 없어야 한다는 것입니다. 보통의 프로그래밍 언어는 이런 공백을 무시하지만, 배쉬에서는 공백이 명령어와 인자를 나누는 기준이라서, 공백을 넣으면 전혀 다른 뜻이 됩니다.

player = "Ralo"
bash: player: command not found

공백을 넣었더니 배쉬가 player를 명령어로, =와 "Ralo"를 그 명령어에 넘기는 인자로 해석했습니다. 그런데 player라는 명령어는 없으니 “command not found” 오류가 났습니다.

따옴표를 쓰는 이유

위에서 오른쪽 값을 "Ralo"처럼 큰따옴표로 감쌌는데, 어차피 모든 값이 문자열이니 따옴표 없이 player=Ralo라고 써도 됩니다. 하지만 큰따옴표에는 안에 든 내용을 통째로 하나의 문자열로 묶는 역할이 있습니다. 간단한 경우에는 따옴표가 없어도 문제가 없지만, 따옴표를 생략하면 가끔 의도와 다른 일이 일어나기 때문에, 항상 큰따옴표를 쓰는 습관을 들이는 것이 좋습니다. 예를 들어 공백이 들어간 값을 따옴표 없이 넣어 보겠습니다.

player=ralo dopa paka
bash: dopa: command not found

변수에 ralo dopa paka가 들어갈 것 같지만, 실제로는 오류가 났습니다. 공백을 기준으로 끊어 읽으니, 배쉬는 이 줄을 “player=ralo라는 설정을 잠깐 붙인 채로 dopa라는 명령어를 paka라는 인자와 함께 실행하라”는 뜻으로 해석한 것입니다. dopa라는 명령어는 없으니 오류가 났고, player에는 아무것도 저장되지 않았습니다. 큰따옴표로 감싸면 이런 문제가 사라집니다.

player="ralo dopa paka"
echo "$player"
ralo dopa paka

변수 읽기

=가 변수에 값을 쓰는 역할이라면, 변수의 값을 읽을 때는 변수 이름 앞에 $를 붙입니다.

player="Ralo"
echo "$player!! $player!! $player!!"
Ralo!! Ralo!! Ralo!!

player에 들어 있는 값 Ralo가 세 번 불려 왔습니다.

Note!!를 배쉬 창에 직접 입력할 때

위 예제를 배쉬 창(또는 맥의 zsh)에 직접 입력하면 결과가 이상하게 나올 수 있습니다. 대화형 셸에서 큰따옴표 안의 !!는 “바로 전에 입력한 명령어”로 바뀌는 기능(history expansion)이 있기 때문입니다. 스크립트 파일로 실행하면 이 기능이 꺼져 있어 문제가 없고, 배쉬 창에서 그대로 따라 해 보고 싶다면 먼저 set +H를 입력해 이 기능을 끄면 됩니다.

변수 이름 바로 뒤에 다른 글자가 붙을 때는, 어디까지가 변수 이름인지 배쉬가 알 수 있도록 중괄호로 감싸 ${변수}처럼 씁니다. 3.4의 스크립트에서도 이 모양을 쓰게 됩니다.

val="2000"
echo "$val_dollars"     # val_dollars라는 (없는) 변수를 찾습니다.
echo "${val}_dollars"   # val의 값 뒤에 _dollars를 붙입니다.

2000_dollars

첫 줄은 val_dollars라는 변수를 찾았는데 그런 변수가 없으니 빈 줄이 출력되었습니다. 배쉬에서는 없는 변수를 읽어도 오류 없이 빈 문자열이 나오기 때문에, 오타가 나도 눈치채기 어렵다는 점을 기억해 두세요.

명령어의 결과를 변수에 담기

변수에 값을 직접 적어 넣을 수도 있지만, 프로그래밍을 하다 보면 다른 명령어가 만들어 낸 결과를 변수에 저장해야 할 때가 많습니다. 이때는 $(명령어)를 씁니다. 이것을 명령어 치환(command substitution)이라고 합니다.

greeting="Hello"
user=$(whoami)
day=$(date +%A)
echo "$greeting $user! Today is $day."
Hello user! Today is Tuesday.

한 줄씩 살펴보겠습니다.

  • whoami는 말 그대로 지금 사용자가 누구인지 출력하는 명령어입니다. user=$(whoami)는 whoami를 실행한 결과를 user에 저장하라는 뜻입니다. 그래서 user에는 컴퓨터의 사용자 이름이 들어갑니다. 여기서는 사용자 이름이 user라서 user가 나왔고, 각자의 컴퓨터에서는 각자의 이름이 나옵니다.
  • date는 지금 날짜와 시각을 출력하는 명령어인데, +%A라는 형식을 붙이면 오늘이 무슨 요일인지만 출력합니다. 그래서 day에는 오늘의 요일이 들어갑니다. (컴퓨터의 언어 설정이 한국어라면 화요일처럼 한국어로 나옵니다.)
  • 마지막 echo는 세 변수의 값을 이어서 인사말을 출력합니다.

참고로 +%A는 date라는 명령어에 넘기는 인자이기 때문에, 명령어와 인자 사이에 반드시 공백이 있어야 합니다. 공백 없이 붙여 쓰면 배쉬는 date+%A 전체를 하나의 명령어 이름으로 읽습니다.

date+%A
bash: date+%A: command not found

환경 변수

지금까지 만든 변수는 지금 열려 있는 셸 안에서만 살아 있습니다. 배쉬 창을 닫으면 사라지고, 스크립트 안에서 만든 변수는 그 스크립트가 끝나면 사라집니다. 또 스크립트를 실행하면 새로운 배쉬가 하나 더 뜨는데, 이 새 배쉬는 바깥 셸에서 만든 변수를 그냥은 볼 수 없습니다. 이것을 직접 확인해 보겠습니다. bash -c '명령'은 새 배쉬를 하나 띄워서 따옴표 안의 명령을 실행하라는 뜻입니다.

fruit="apple"
bash -c 'echo "새 배쉬에서 본 fruit: [$fruit]"'
새 배쉬에서 본 fruit: []

새 배쉬에서는 fruit가 비어 있습니다. 변수를 새로 띄우는 프로그램에도 물려주고 싶다면 export를 붙입니다.

export fruit
bash -c 'echo "새 배쉬에서 본 fruit: [$fruit]"'
새 배쉬에서 본 fruit: [apple]

이렇게 export된 변수를 환경 변수(environment variable)라고 합니다. 시스템에는 미리 설정된 환경 변수들이 있어서, 셸을 열 때마다 자동으로 만들어지고 거기서 실행하는 모든 프로그램에 전달됩니다. 대표적인 것이 HOME과 PATH입니다.

echo $HOME
echo $PATH
/home/user
/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin

HOME은 사용자의 홈 디렉터리입니다. PATH는 조금 더 중요한데, 배쉬가 명령어를 찾아볼 폴더들의 목록입니다. 폴더들이 :로 구분되어 있습니다. 우리가 ls라고 입력하면, 배쉬는 PATH에 적힌 폴더들을 앞에서부터 차례로 뒤져서 ls라는 이름의 실행 파일을 찾고, 처음 찾은 것을 실행합니다. 어떤 명령어가 실제로 어디에 있는지는 which로 확인할 수 있습니다.

which ls bash
/usr/bin/ls
/usr/bin/bash

앞에서 player나 dopa에 “command not found”가 난 것도, PATH의 어느 폴더에도 그런 이름의 실행 파일이 없었기 때문입니다. 각자의 컴퓨터에서는 PATH와 which의 결과가 조금씩 다르게 나옵니다.

조건문

간단한 작업은 명령어 하나로 끝나지만, 복잡한 작업은 여러 명령어를 엮어서 만듭니다. 명령어는 보통 위에서 아래로 차례로 실행되는데, 상황에 따라 순서를 바꾸거나 일부 명령만 실행해야 할 때가 있습니다. 이를 위한 문법을 제어 구조(control structure)라고 합니다.

대표적인 제어 구조는 조건에 따라 명령을 실행하기도, 건너뛰기도 하는 if-else 문입니다. 거의 모든 프로그래밍 언어에 있고, 문법만 조금씩 다릅니다. 배쉬에서는 다음과 같이 씁니다.

if <조건>; then
    <조건이 참일 때 할 일>
else
    <조건이 거짓일 때 할 일>
fi

if 다음에 조건을 적고, ;로 끊은 다음 then을 적습니다. (;가 싫다면 then을 다음 줄로 내려도 됩니다.) 그리고 조건이 만족될 때 할 일을 적고, else 다음에 조건이 만족되지 않을 때 할 일을 적습니다.

다른 언어에서는 중괄호 같은 것으로 if 문이 어디서 끝나는지 표시하는데, 배쉬에는 그런 것이 없어 보여 의아할 수 있습니다. 물론 있습니다. 맨 끝의 fi가 그 역할을 합니다. 배쉬는 if로 if 문을 시작하고, if를 거꾸로 뒤집은 fi로 끝맺습니다.

조건이 여러 개라면, 앞의 조건이 모두 거짓일 때 확인할 조건을 elif(else if)로 이어 적습니다.

if <조건1>; then
    <조건1이 참일 때 할 일>
elif <조건2>; then
    <조건1은 거짓이고 조건2가 참일 때 할 일>
else
    <둘 다 거짓일 때 할 일>
fi

대괄호 안의 조건식

조건 자리에는 보통 대괄호 [ ] 안에 조건식을 적습니다. 이중 대괄호 [[ ]]나 이중 소괄호 (( ))를 쓰기도 하고, 괄호 없이 명령어를 그대로 적기도 하는데, 가장 기본은 대괄호입니다.

a=300
b=200
if [ $a -lt $b ]; then
    echo "$a is less than $b!"
else
    echo "$a is greater than $b!"
fi
300 is greater than 200!

조건식 $a -lt $b를 뜯어보면, 먼저 $가 붙어 있으니 a와 b의 값을 불러옵니다. 그리고 -lt는 less than의 머리글자를 딴 연산자로, 왼쪽 값이 오른쪽 값보다 숫자로서 작으면 참, 아니면 거짓이 됩니다.

부등호 < 대신 -lt 같은 이상한 연산자를 쓰는 이유는, 대괄호 안에서 <와 >가 지난 글에서 본 리다이렉션 기호로 해석되기 때문입니다. [ $a > $b ]라고 쓰면 비교가 아니라 “200이라는 파일로 출력을 보내라”는 뜻이 되어 버립니다. 게다가 배쉬의 값은 모두 문자열이라서, 이 값들을 숫자로 바꿔서 비교하라고 따로 알려 줄 필요도 있습니다. -lt 같은 연산자가 바로 그 일을 합니다.

또 하나 주의할 점은, 대괄호와 그 안의 조건 사이에 반드시 공백이 있어야 한다는 것입니다. 사실 [는 괄호처럼 생겼지만 그 자체가 하나의 명령어라서, 공백 없이 붙여 쓰면 앞에서 본 것처럼 엉뚱한 이름의 명령어를 찾게 됩니다.

if [$a -lt $b]; then echo "작다"; fi
bash: [300: command not found

대괄호 안에서 쓸 수 있는 대표적인 연산자는 다음과 같습니다.

연산자 뜻 예시
-eq, -ne 숫자가 같다, 다르다 (equal, not equal) [ $a -eq 300 ]
-lt, -le 왼쪽이 작다, 작거나 같다 (less than, less or equal) [ $a -le $b ]
-gt, -ge 왼쪽이 크다, 크거나 같다 (greater than, greater or equal) [ $a -gt $b ]
=, != 문자열이 같다, 다르다 [ "$player" = "Ralo" ]
-z, -n 문자열이 비어 있다, 비어 있지 않다 [ -z "$name" ]
-e, -f, -d 경로가 존재한다, 파일이다, 폴더다 [ -f data.csv ]
! 조건을 뒤집는다 [ ! -d output ]

이중 소괄호 (( ))

대괄호와 -lt 같은 연산자를 쓰는 것이 정석이지만, 이중 소괄호 (( )) 안에 조건을 적으면 안의 값들을 모두 숫자로 받아들이기 때문에 ==, !=, <, <=, >, >=를 그대로 쓸 수 있습니다.

a=300
b=200
if (($a < $b)); then
    echo "$a is less than $b!"
else
    echo "$a is greater than $b!"
fi
300 is greater than 200!

(( )) 안에서는 모든 것을 숫자 계산으로 처리하기 때문에, 괄호와 조건 사이에 공백이 없어도 되고, 변수 앞의 $도 생략할 수 있습니다. (((a < b))라고 써도 됩니다.)

이쪽이 훨씬 편해 보이지만, 그래도 대괄호 문법을 알아 두어야 하는 이유가 있습니다. 대괄호는 셸의 가장 표준적인 문법이라 오래된 셸이나 다른 셸에서도 거의 다 통하고, 위의 표처럼 숫자 비교뿐 아니라 파일이 있는지, 문자열이 비어 있는지 같은 다양한 검사를 할 수 있습니다. 반면 (( ))는 배쉬 같은 비교적 최신 셸에서만 지원하는 확장 문법이고, 숫자 계산만 할 수 있습니다.

종료 코드: 참이 0인 이유

조건문이 돌려주는 값에는 조금 주의가 필요합니다. 보통 프로그래밍 언어에서는 참이면 1(또는 0이 아닌 값), 거짓이면 0인데, 셸에서는 정반대로 참이면 0, 거짓이면 0이 아닌 값입니다.

이렇게 헷갈리게 만든 데에는 이유가 있습니다. 셸의 모든 명령어는 실행이 끝나면 종료 코드(exit code)라는 숫자를 남깁니다. 성공했으면 0, 실패했으면 0이 아닌 값입니다. 성공하는 경우는 하나뿐이지만 실패하는 이유는 여러 가지이니, 0이 아닌 여러 값에 실패의 원인을 하나씩 대응시킬 수 있도록 한 것입니다. 조건문도 이 약속을 따릅니다. 조건이 만족되었다는 것은 검사가 “성공”했다는 뜻이니 0을, 조건이 틀렸다는 것은 “실패”했다는 뜻이니 0이 아닌 값을 남깁니다. 그리고 if는 사실 대괄호의 결과를 보는 것이 아니라, 그 자리에 있는 명령어의 종료 코드가 0인지를 봅니다.

바로 전 명령어의 종료 코드는 $?로 확인할 수 있습니다.

pwd
echo $?
/home/user/scripting
0

배쉬는 명령어를 하나씩 실행하면서, 방금 끝난 명령어의 종료 코드를 기억해 둡니다. 그래서 echo $?는 echo 자신이 아니라 바로 앞의 pwd의 종료 코드를 보여 주고, pwd가 잘 실행되었으니 0이 나왔습니다. 실패하는 명령어와 조건식도 확인해 보겠습니다.

ls no-such-file.txt
echo $?
[ 3 -lt 5 ]
echo $?
[ 5 -lt 3 ]
echo $?
ls: cannot access 'no-such-file.txt': No such file or directory
2
0
1

없는 파일을 ls하니 오류와 함께 0이 아닌 값 2가 남았습니다. [ 3 -lt 5 ]는 참이니 0, [ 5 -lt 3 ]은 거짓이니 1입니다.

반복문

제어 구조에서 빼놓을 수 없는 것이 반복문(loop)입니다. 이름처럼 같은 작업을 여러 번 반복할 때 씁니다. 가장 대표적인 것은 for 문으로, 다음과 같은 구조입니다.

for <변수> in <목록>; do
    <할 일>
done

파이썬의 for 문처럼, 목록에 든 값을 하나씩 차례로 <변수>에 넣으면서 <할 일>을 반복합니다. 그리고 done으로 끝납니다. 목록은 다음처럼 값을 공백으로 띄어 적으면 됩니다.

for i in 1 2 3; do
    echo $i
done
1
2
3

목록이라고는 했지만 배쉬에는 파이썬의 리스트 같은 자료형이 따로 있는 것이 아니라, 공백을 기준으로 값을 하나씩 끊어서 목록처럼 다룹니다. 앞에서 어차피 모든 값이 문자열인데도 큰따옴표를 쓰는 습관이 중요하다고 했던 이유가 여기에도 있습니다. 도파 랄로 파카 레츠고를 하나의 문자열로 다루고 싶었더라도, 따옴표 없이 적으면 공백마다 끊어서 네 번 반복합니다.

for name in 도파 랄로 파카 레츠고; do
    echo "[$name]"
done
[도파]
[랄로]
[파카]
[레츠고]
for name in "도파 랄로 파카 레츠고"; do
    echo "[$name]"
done
[도파 랄로 파카 레츠고]

목록을 직접 적는 대신, 반복 횟수를 세는 변수를 하나 두고 그 값을 바꿔 가며 반복하는 경우도 많습니다. 이때는 이중 소괄호 안에 C 언어의 for 문처럼 적습니다.

for ((i=0; i<4; i++)); do
    echo $i
done
0
1
2
3

i = 0에서 출발해서, i < 4가 참인 동안 안의 명령을 실행하고, 한 번 실행할 때마다 i를 1씩 올립니다(i++).

숫자 계산

(( ))는 조건에만 쓰는 것이 아니라 숫자 계산을 할 때 씁니다. 배쉬에서는 모든 값이 기본적으로 문자열이기 때문에, 프로그래밍을 해 본 사람이라면 누구나 아는 i = i + 1 같은 표현도 그대로 쓸 수 없습니다. 그냥 쓰면 숫자 덧셈이 아니라 글자를 이어 붙인 것이 됩니다.

i=1
i=$i+1
echo $i
1+1

“이건 숫자 계산입니다”라는 맥락을 배쉬에 알려 주려면, let 명령어 뒤에 식을 적거나, (( )) 안에 식을 적어야 합니다. 계산 결과를 값으로 꺼내 쓰고 싶을 때는 $(( ))를 씁니다.

i=1
let i=i+1
echo $i
((i=i+1))
echo $i
echo "10을 3으로 나눈 몫: $((10 / 3)), 나머지: $((10 % 3))"
2
3
10을 3으로 나눈 몫: 3, 나머지: 1

마지막 줄에서 보듯, 배쉬의 산술 계산은 정수만 다룹니다. 10을 3으로 나누면 3.333…이 아니라 몫인 3이 나옵니다. 소수 계산이 필요하면 awk를 쓰거나 파이썬으로 넘어가는 편이 낫습니다.

while 문

while 문은 if처럼 조건을 확인하고, 조건이 참인 동안 안의 명령을 반복합니다. 조건을 적는 방법은 if와 같습니다.

while <조건>; do
    <할 일>
done

예를 들어 1부터 차례로 더해서 합이 20을 넘을 때까지 반복해 보겠습니다.

n=0
sum=0
while [ $sum -le 20 ]; do
    ((n++))
    ((sum += n))
    echo "n=$n, sum=$sum"
done
n=1, sum=1
n=2, sum=3
n=3, sum=6
n=4, sum=10
n=5, sum=15
n=6, sum=21

while 문을 쓸 때는 조건이 언젠가 거짓이 되도록 해야 합니다. 그렇지 않으면 반복이 끝나지 않습니다. 배쉬 창에서 무언가가 끝나지 않고 계속 돌 때는 Ctrl + C를 누르면 멈출 수 있습니다.

스트림: 0번 입구와 1번, 2번 출구

배쉬에서 가장 많이 쓰게 될 구조는 결국 파이프입니다. 지난 글에서 파이프가 앞 명령어의 출력을 다음 명령어의 입력으로 넘긴다고 했는데, 이것은 배쉬의 스트림(stream)으로 설명할 수 있습니다. 배쉬의 모든 명령어에는 다음 세 개의 통로가 있습니다.

번호 이름 기본으로 연결된 곳
0 표준 입력(standard input, stdin) 키보드
1 표준 출력(standard output, stdout) 화면
2 표준 에러(standard error, stderr) 화면

명령어는 0번 입구로 데이터를 받아서, 결과는 1번 출구로, 오류 메시지는 2번 출구로 내보냅니다. 파이프는 앞 명령어의 1번 출구를 다음 명령어의 0번 입구에 연결합니다. 그러면 데이터가 어딘가에 고정되어 있는 것이 아니라, 0번으로 들어와 명령어를 거쳐 1번으로 나가고, 다시 다음 명령어의 0번으로 들어가는 물레방아 같은 흐름이 만들어집니다. 간단한 예를 보겠습니다.

ls -al | wc -l
4

ls -al은 지금 폴더의 모든 파일과 폴더 목록을 자세히 출력하는데, 이 출력이 파이프를 통해 wc -l로 넘어가서 줄 수가 세어졌습니다.

tee: 출력을 두 갈래로

파이프는 출력을 한 곳으로만 넘기는데, 출력을 두 갈래로 나누고 싶을 때가 있습니다. 이때 쓰는 명령어가 tee입니다. 이름은 알파벳 T에서 왔는데, T자 모양의 배관을 다는 것과 똑같습니다.

date | tee date_file.txt
Tue Nov  3 23:28:58 UTC 2026

date는 지금 날짜와 시각을 출력하는 명령어입니다. 그냥 파이프만 썼다면 date의 출력은 다음 명령어로만 넘어가지만, tee를 달았기 때문에 출력이 두 갈래로 나뉘어 하나는 date_file.txt라는 파일에 저장되고, 동시에 다른 하나는 화면에 출력되었습니다. 파일에도 잘 들어갔는지 확인해 보겠습니다.

cat date_file.txt
Tue Nov  3 23:28:58 UTC 2026

tee 뒤에 다시 |를 이어서, 화면으로 가던 갈래를 또 다른 명령어의 입력으로 넘길 수도 있습니다.

리다이렉션 <, >, 2>

파이프가 명령어와 명령어를 잇는다면, 지난 글에서 본 리다이렉션은 명령어와 파일을 잇습니다. >는 1번 출구를 화면 대신 파일로 돌리고, <는 0번 입구를 키보드 대신 파일에서 받도록 돌립니다. 예를 들어 다음과 같은 file1.txt가 있다고 해 보겠습니다.

cat file1.txt
banana
cherry
apple
durian
sort < file1.txt > temp.txt
cat temp.txt
apple
banana
cherry
durian

첫 줄은 file1.txt의 내용을 sort(정렬하는 명령어)의 입력으로 넣고(< file1.txt), sort가 정렬한 출력을 화면 대신 temp.txt에 저장하라(> temp.txt)는 뜻입니다. 앞에서 말했듯이 >는 덮어쓰기이므로, temp.txt에 원래 무언가 있었다면 사라지고 정렬 결과만 남습니다.

오류 메시지가 나오는 2번 출구는 2>로 돌릴 수 있습니다. 오류 메시지를 따로 모아 두거나, 보기 싫은 오류를 버리고 싶을 때 씁니다.

ls file1.txt no-such-file.txt 2> errors.txt
echo "--- errors.txt 안의 내용 ---"
cat errors.txt
file1.txt
--- errors.txt 안의 내용 ---
ls: cannot access 'no-such-file.txt': No such file or directory

정상 출력(file1.txt)은 1번 출구로 나가서 화면에 보였고, 오류 메시지는 2번 출구로 나가서 errors.txt에 저장되었습니다.

스크립트 파일 만들고 실행하기

이제 지금까지 배운 것을 파일에 적어서 실행해 보겠습니다. C나 자바를 공부해 보셨다면, 처음에 텍스트 파일에 소스 코드를 적고 터미널에서 컴파일해서 실행해 본 적이 있을 것입니다. 배쉬 스크립트도 비슷합니다. 텍스트 파일에 명령어들을 적고, 확장자를 .sh로 저장한 다음, 배쉬로 실행합니다.

쉬뱅

.sh 파일에는 지금까지 공부한 명령어와 제어 구조를 그대로 적으면 되는데, 주의할 점은 맨 첫 줄에 쉬뱅(shebang)을 적는 것입니다.

#!/bin/bash
# 이 아래에 코드를 적습니다.

쉬뱅은 이 파일을 실행할 때 “이 코드는 이 경로에 있는 배쉬로 해석하라”고 컴퓨터에 알려 주는 표시입니다. #!가 먼저 오고, 그 뒤에 배쉬의 경로가 옵니다. 배쉬의 경로는 which bash로 확인할 수 있는데, 운영체제마다 다릅니다.

  • Windows
  • macOS
  • Linux
  • Android (Termux)

깃 배쉬와 WSL에서는 보통 다음과 같이 나옵니다.

$ which bash
/usr/bin/bash

깃 배쉬에서는 #!/bin/bash와 #!/usr/bin/bash가 모두 동작합니다.

메모장으로 스크립트를 쓸 때는 줄바꿈 형식에 주의하세요. 윈도우는 줄 끝을 CRLF(\r\n)로, 리눅스와 맥은 LF(\n)로 표시하는데, 배쉬는 \r을 명령어의 일부로 읽어서 $'\r': command not found 같은 오류를 냅니다. 그래서 스크립트는 메모장보다 VS Code나 Notepad++ 같은 편집기로 쓰고, 줄바꿈 형식을 LF로 맞춰 저장하는 것이 안전합니다. (VS Code에서는 오른쪽 아래 상태 표시줄의 CRLF를 눌러 LF로 바꿀 수 있습니다.) 이미 CRLF로 저장해 버린 파일은 깃 배쉬에서 sed -i 's/\r$//' example.sh로 고칠 수 있습니다.

$ which bash
/bin/bash

Homebrew로 최신 배쉬를 설치했다면 /opt/homebrew/bin/bash(애플 실리콘 맥) 또는 /usr/local/bin/bash(인텔 맥)가 나옵니다. 스크립트는 텍스트 편집기나 VS Code로 쓰면 되는데, 기본 앱인 텍스트 편집기를 쓸 때는 “포맷 → 일반 텍스트 만들기”로 바꿔서 저장해야 합니다.

$ which bash
/usr/bin/bash

대부분의 배포판에서 /bin/bash와 /usr/bin/bash는 같은 파일이라 어느 쪽을 써도 됩니다. 스크립트는 nano example.sh처럼 터미널 안의 편집기로 쓰거나, 그래픽 편집기를 쓰면 됩니다.

$ which bash
/data/data/com.termux/files/usr/bin/bash

Termux에는 /bin/bash가 없지만, Termux가 #!/bin/bash나 #!/usr/bin/env bash 같은 흔한 쉬뱅을 자동으로 자기 경로로 바꿔 실행해 주기 때문에 보통은 그대로 써도 됩니다. 스크립트는 nano example.sh처럼 터미널 안의 편집기로 씁니다. (nano가 없다면 pkg install nano로 설치합니다.)

운영체제마다 경로가 다르니, 여러 환경에서 돌아가야 하는 스크립트에는 #!/usr/bin/env bash라는 쉬뱅도 많이 씁니다. “PATH에서 bash를 찾아서 그것으로 실행하라”는 뜻이라, 배쉬가 어디에 설치되어 있든 동작합니다.

실행 권한 주고 실행하기

예를 들어 다음 내용을 example.sh라는 이름으로 저장했다고 해 보겠습니다.

cat example.sh
#!/usr/bin/env bash
# 인사말을 출력하고, 1부터 3까지 세는 스크립트
greeting="Hello"
user=$(whoami)
echo "$greeting $user!"

for ((i=1; i<=3; i++)); do
    echo "count: $i"
done

이 파일을 바로 실행해 보면, 권한이 없다는 오류가 납니다.

./example.sh
bash: ./example.sh: Permission denied

새로 만든 텍스트 파일은 읽고 쓸 수만 있고 실행할 수는 없는 상태이기 때문입니다. chmod +x로 이 파일을 실행 가능한(executable) 파일로 바꿔 줍니다. 물론 배쉬는 example.sh가 들어 있는 폴더를 바라보고 있어야 합니다.

chmod +x example.sh
./example.sh
Hello user!
count: 1
count: 2
count: 3

이제 스크립트가 실행됩니다. 실행할 때 example.sh가 아니라 ./example.sh라고 적는 이유는, 앞에서 본 PATH 때문입니다. 그냥 example.sh라고 적으면 배쉬는 PATH에 있는 폴더들에서만 example.sh를 찾는데, 지금 폴더는 보통 PATH에 들어 있지 않습니다. 그래서 “지금 폴더(.)에 있는 example.sh”라고 경로를 직접 알려 주는 것입니다.

example.sh
bash: example.sh: command not found

실행 권한을 주지 않고 bash example.sh처럼 배쉬에게 파일을 직접 넘겨서 실행하는 방법도 있습니다. 이때는 쉬뱅 줄이 무시되고, 지금 쓰는 배쉬가 파일을 읽어서 실행합니다. 또, 윈도우의 깃 배쉬는 리눅스와 파일 권한을 다루는 방식이 달라서, .sh 파일이 chmod 없이도 실행되는 경우가 많습니다.

정리

  • 변수는 이름="값"처럼 = 양옆에 공백 없이 만들고, $이름으로 읽습니다. 값은 항상 큰따옴표로 감싸는 습관을 들입니다.
  • $(명령어)로 명령어의 결과를 변수에 담고, export한 환경 변수는 새로 띄우는 프로그램에도 전달됩니다. PATH는 명령어를 찾아볼 폴더 목록입니다.
  • if [ 조건 ]; then … fi로 조건에 따라 실행하고, 조건에는 -lt, -eq 같은 연산자를 씁니다. 셸에서는 성공(참)이 0이고, $?로 바로 전 명령의 종료 코드를 봅니다.
  • for … do … done과 while … do … done으로 반복하고, 숫자 계산은 (( ))나 let, $(( ))로 합니다.
  • 명령어에는 표준 입력(0), 표준 출력(1), 표준 에러(2)가 있고, |, tee, <, >, 2>로 흐름을 바꿉니다.
  • 스크립트는 첫 줄에 쉬뱅을 적은 .sh 파일로 저장하고, chmod +x로 실행 권한을 준 뒤 ./파일이름.sh로 실행합니다.
