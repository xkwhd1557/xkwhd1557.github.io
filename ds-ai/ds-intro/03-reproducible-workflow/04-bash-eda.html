3.4 배쉬로 하는 탐색적 데이터 분석

3장 재현 가능한 작업 환경 · 퀴즈쇼 데이터 훑어보기

데이터 사이언스·AI
데이터 사이언스 개론
미국 퀴즈쇼 Jeopardy! 데이터와 같은 형식의 연습 데이터를 배쉬로 탐색합니다. 압축 풀기, 파일 권한, 와일드카드, head·tail·wc, sed와 grep, xargs, 반복문 스크립트로 상금별·카테고리별 문제를 골라내고 세어 봅니다.
Published

November 4, 2026

들어가며

3.2와 3.3에서 배쉬의 명령어와 스크립팅을 살펴보았습니다. 이번 글에서는 이것들을 가지고 실제로 데이터를 훑어보는 탐색적 데이터 분석(exploratory data analysis, EDA)의 첫 단계를 해 보겠습니다. 3.1에서 말했듯이, 큰 데이터를 파이썬으로 본격적으로 분석하기 전에 배쉬로 먼저 가볍게 구조를 파악하고 필요한 부분만 골라내는 단계입니다.

데이터: 퀴즈쇼 Jeopardy!

예제로 쓸 데이터는 미국의 퀴즈쇼 Jeopardy!의 문제 데이터입니다. 이 퀴즈쇼는 여러 카테고리에 각각 상금이 다른 문제가 걸려 있고, 참가자 중 한 명이 버저를 눌러 답을 말하는 형식입니다. 라운드마다 상금이 다른데, 첫 라운드인 Jeopardy! 라운드는 200달러부터 1,000달러까지, 두 번째 라운드인 Double Jeopardy! 라운드는 400달러부터 2,000달러까지의 문제가 있고, 마지막 Final Jeopardy! 라운드에는 정해진 상금 없이 참가자가 건 금액을 걸고 한 문제를 풉니다.

원본 데이터는 데이터 과학자들의 커뮤니티인 캐글(Kaggle)에서 받을 수 있습니다.1 캐글은 구글이 운영하는 플랫폼으로, 공개 데이터를 내려받거나, 다른 사람의 분석을 참고하거나, 기업이 상금을 걸고 여는 데이터 분석 대회에 참가할 수 있습니다. 대회 성적이 좋으면 그 자체로 좋은 경력이 되기도 해서, 실제 데이터로 배우고 경쟁하며 포트폴리오를 쌓는 종합 플랫폼이라고 할 수 있습니다. 무엇보다 꽤 질 좋은 공개 데이터를 많이 얻을 수 있습니다.

이 데이터는 오랜 기간의 방송 문제를 모아 둔 것이라 꽤 큽니다. 그래서 이 글에서는 그중 2004년에 방송된 문제만 골라서, 방송 날짜별로 파일을 나눈 형태로 실습합니다. 실습용 데이터는 아래에서 받을 수 있습니다.

  • 연습 데이터: jeopardy-2004-sample.tar.gz

이 연습 데이터는 원본과 형식만 똑같이 만든 가상 데이터입니다. 2004년의 평일마다 방송이 하나씩 있었다고 치고, 방송마다 Jeopardy! 라운드 30문제, Double Jeopardy! 라운드 30문제, Final Jeopardy! 1문제를 넣었습니다. 문제와 정답은 Sample clue #1, answer 1처럼 가짜 문장으로 채워 두었기 때문에, 아래에 나오는 개수나 빈도는 실제 방송과 다릅니다. 명령어를 익히는 데에는 이 연습 데이터로 충분하고, 실제 데이터로 해 보고 싶다면 아래의 스크립트로 원본에서 같은 형태의 파일을 직접 만들 수 있습니다.

원본 데이터로 직접 만들기

이 부분은 건너뛰어도 됩니다. 원본 데이터를 쓰려면 먼저 캐글에 로그인한 뒤 데이터 페이지에서 archive.zip을 내려받고, 압축을 풀어 200k_questions.json 파일을 꺼냅니다. 그리고 JSON 파일을 다루는 jq라는 프로그램이 필요합니다.

  • Windows
  • macOS
  • Linux
  • Android (Termux)

깃 배쉬에는 jq가 들어 있지 않습니다. 파워셸에서 다음 명령으로 설치한 뒤, 깃 배쉬를 새로 열면 됩니다. (WSL의 우분투를 쓴다면 Linux 탭의 방법을 따르면 됩니다.)

winget install jqlang.jq

archive.zip은 탐색기에서 마우스 오른쪽 버튼을 눌러 “압축 풀기”로 풀면 됩니다.

맥OS 15(세쿼이아)부터는 jq가 기본으로 들어 있습니다. 터미널에 jq --version을 입력해서 버전이 나오지 않는다면, Homebrew로 설치합니다.

brew install jq

archive.zip은 Finder에서 더블클릭하거나, 터미널에서 unzip archive.zip으로 풀면 됩니다.

우분투라면 다음과 같이 설치합니다.

sudo apt install jq unzip

archive.zip은 unzip archive.zip으로 풀면 됩니다.

pkg install jq unzip

내려받은 archive.zip은 ~/storage/downloads에 있으니, Termux 홈으로 복사한 뒤 unzip archive.zip으로 풀면 됩니다.

그다음 200k_questions.json과 같은 폴더에 다음 스크립트를 split.sh로 저장하고, 3.3에서 본 대로 chmod +x split.sh와 ./split.sh로 실행합니다. 처음 보는 문법이 조금 섞여 있지만, 주석을 따라 읽어 보면 3.3에서 배운 변수, 파이프, 반복문, 리다이렉션으로 이루어져 있다는 것을 알 수 있습니다.

#!/usr/bin/env bash
# 원본 JSON에서 특정 연도의 문제만 뽑아 날짜별 파일로 나누고, 하나의 압축 파일로 묶습니다.
INPUT="200k_questions.json"   # 캐글에서 받은 원본 파일
YEAR="2004"                   # 뽑아낼 연도
OUT_DIR="split_by_date"       # 날짜별 파일을 모을 폴더
ARCHIVE="jeopardy-${YEAR}.tar.gz"

mkdir -p "$OUT_DIR"

# 1. 해당 연도의 문제만 한 줄에 하나씩 뽑아서, 방송 날짜별 임시 파일에 모읍니다.
#    air_date가 문자열이 아닌 행(결측치 등)은 건너뜁니다.
jq -c --arg y "$YEAR" '.[] | select((.air_date | type) == "string" and (.air_date | startswith($y)))' "$INPUT" |
while IFS= read -r row; do
    date=${row#*\"air_date\":\"}   # "air_date":" 앞부분을 잘라 내고
    date=${date%%\"*}              # 다음 따옴표부터 뒷부분을 잘라 내면 날짜만 남습니다.
    printf '%s\n' "$row" >> "$OUT_DIR/$date.tmp"
done

# 2. 날짜별 임시 파일을 [ ... ] 배열 형식의 .json 파일로 바꿉니다.
for file in "$OUT_DIR"/*.tmp; do
    jq -s '.' "$file" > "${file%.tmp}.json" && rm "$file"
done

# 3. 폴더 전체를 하나의 압축 파일로 묶습니다.
tar -czf "$ARCHIVE" "$OUT_DIR"
echo "완료: $(ls "$OUT_DIR" | wc -l)개 날짜 파일 -> $ARCHIVE"

실행이 끝나면 jeopardy-2004.tar.gz가 생깁니다. 아래 실습에서 jeopardy-2004-sample.tar.gz 대신 이 파일 이름을 쓰면 됩니다.

JSON이란?

데이터 파일의 확장자는 .json입니다. JSON(JavaScript Object Notation)은 컴퓨터들이 인터넷에서 데이터를 주고받을 때 가장 많이 쓰는 텍스트 데이터 형식입니다. 이름에 자바스크립트가 들어 있지만, 파이썬, 배쉬, C 등 거의 모든 언어와 시스템에서 읽고 쓸 수 있는 표준 형식입니다. 이 데이터의 문제 하나는 다음과 같이 생겼습니다.

{
  "category": "LITERATURE",
  "air_date": "2004-01-15",
  "question": "Sample clue #2014",
  "value": "$200",
  "answer": "answer 2014",
  "round": "Jeopardy!",
  "show_number": "4474"
}

중괄호 { }는 데이터 한 덩어리, 여기서는 문제 하나를 감쌉니다. 생김새가 파이썬의 딕셔너리와 똑같습니다. "category"라는 키(key)에 "LITERATURE"라는 값(value)이 들어 있는 식으로, 카테고리, 방송 날짜, 문제, 상금, 정답, 라운드, 방송 회차가 들어 있습니다. 원본 데이터에서는 question과 answer에 실제 문제와 정답이 들어 있고, Final Jeopardy! 문제는 정해진 상금이 없어서 value가 null(값 없음)입니다. 그리고 하나의 .json 파일에는 이런 중괄호 덩어리 여러 개가 대괄호 [ ] 안에 쉼표로 구분되어 들어 있습니다.

압축 풀고 둘러보기

내려받은 파일을 실습 폴더에 옮기고, 배쉬가 그 폴더를 바라보게 한 다음 시작합니다. 여기서는 홈 아래의 eda라는 폴더를 씁니다.

cd ~/eda
ls
jeopardy-2004-sample.tar.gz

데이터를 다루려면 먼저 압축을 풀어야 합니다. .tar.gz 파일은 tar로 풉니다.

tar -xzf jeopardy-2004-sample.tar.gz
ls
jeopardy-2004-sample.tar.gz  split_by_date

자세히 보기: ls -la와 파일 권한

ls에는 대표적으로 -a와 -l이라는 옵션이 있습니다. -a(all)는 이름이 .으로 시작하는 숨겨진 파일까지 모두 보여 주고, -l(long)은 파일마다 자세한 정보를 한 줄씩 보여 줍니다. 둘을 합친 ls -la로 폴더 안을 보겠습니다. 파일이 많으니 앞의 5줄만 보겠습니다.

ls -la split_by_date | head -n 5
total 4212
drwxr-xr-x 2 user user 16384 Nov  3 23:19 .
drwxrwxr-x 3 user user  4096 Nov  3 23:31 ..
-rw-r--r-- 1 user user 12794 Nov  3 23:19 2004-01-01.json
-rw-r--r-- 1 user user 12825 Nov  3 23:19 2004-01-02.json

맨 위의 total은 이 파일들이 디스크에서 차지하는 공간을 블록 단위로 나타낸 값이라 신경 쓰지 않아도 됩니다. 그 아래의 이름이 .과 ..인 두 줄은 지금 보고 있는 폴더 자신(.)과 그 위의 폴더(..)에 대한 정보입니다. 그 아래가 각 파일의 정보인데, 한 줄을 뜯어보면 다음과 같습니다.

  • -rw-r--r--: 파일의 종류와 권한(permission)입니다. 아래에서 자세히 봅니다.
  • 1: 하드 링크의 수입니다. 보통 파일은 1이라 신경 쓰지 않아도 됩니다.
  • user user: 파일의 소유자와, 그 소유자가 속한 그룹입니다.
  • 그다음 숫자: 파일의 크기(바이트)입니다.
  • 날짜와 시각: 마지막으로 수정된 때입니다.
  • 마지막: 파일 이름입니다.

권한을 나타내는 10글자 가운데 첫 글자는 종류로, -는 일반 파일, d는 폴더(directory)입니다. 나머지 9글자는 3글자씩 끊어서 차례로 소유자, 그룹, 그 밖의 모든 사람의 권한을 나타냅니다. 각 3글자는 순서대로 읽기(r, read), 쓰기(w, write), 실행(x, execute) 권한이 있는지를 뜻하고, 권한이 없으면 그 자리에 -가 옵니다. 그래서 -rw-r--r--은 “일반 파일이고, 소유자는 읽고 쓸 수 있고, 그룹과 다른 사람은 읽기만 할 수 있다”는 뜻입니다. 3.3에서 chmod +x로 스크립트에 실행 권한을 줬던 것이 바로 이 x 자리를 켜는 일이었습니다. 폴더(d)에서 x는 그 폴더 안으로 들어갈 수 있는 권한을 뜻합니다. (깃 배쉬와 Termux의 내부 저장소에서는 이 권한 표시가 실제 권한과 다를 수 있습니다.)

자주 쓰는 명령어에 별명 붙이기: alias

ls -la처럼 자주 쓰는 명령어를 매번 치기 귀찮다면, alias로 짧은 별명을 붙일 수 있습니다.

alias ll="ls -la"
ll split_by_date | head -n 3
total 4212
drwxr-xr-x 2 user user 16384 Nov  3 23:19 .
drwxrwxr-x 3 user user  4096 Nov  3 23:31 ..

이제 ll이라고만 쳐도 ls -la가 실행됩니다. 다만 이렇게 만든 별명은 지금 열린 셸에서만 유효하고, 배쉬 창을 닫으면 사라집니다. 계속 쓰고 싶다면 홈 디렉터리의 .bashrc(맥의 zsh라면 .zshrc)라는 설정 파일 끝에 이 줄을 적어 두면, 셸을 열 때마다 자동으로 설정됩니다. (깃 배쉬에서도 홈 디렉터리에 .bashrc를 만들어 쓰면 됩니다.)

이제 데이터가 들어 있는 폴더로 들어갑니다. 이렇게 해 두면 앞으로는 파일 이름 앞에 매번 split_by_date/를 붙이지 않아도 됩니다.

cd split_by_date
pwd
/home/user/eda/split_by_date

와일드카드로 파일 고르기

셸에는 와일드카드(wildcard)라는 기능이 있습니다. 파일이 아주 많을 때, 이름이 특정한 모양인 파일만 골라내고 싶을 수 있습니다. 이때 와일드카드를 씁니다. 우리 파일들은 모두 2004-01-05.json처럼 연도-월-일.json 모양의 이름입니다.

?: 딱 한 글자

1월의 데이터만 골라내고 싶다면 다음과 같이 씁니다.

ls 2004-01-??.json
2004-01-01.json  2004-01-09.json  2004-01-19.json  2004-01-27.json
2004-01-02.json  2004-01-12.json  2004-01-20.json  2004-01-28.json
2004-01-05.json  2004-01-13.json  2004-01-21.json  2004-01-29.json
2004-01-06.json  2004-01-14.json  2004-01-22.json  2004-01-30.json
2004-01-07.json  2004-01-15.json  2004-01-23.json
2004-01-08.json  2004-01-16.json  2004-01-26.json

배쉬는 2004-01-까지는 똑같고, ?? 자리에는 아무 글자나 와도 되는 이름의 파일을 찾아서 ls에 넘깁니다. 중요한 것은 물음표 ? 하나가 딱 한 글자만 대신한다는 점입니다. 그래서 ?를 하나만 쓰면 어떻게 될까요?

ls 2004-01-?.json
ls: cannot access '2004-01-?.json': No such file or directory

2004-01- 뒤에 딱 한 글자만 오는 파일은 없으니, 그런 파일이 없다는 오류가 납니다. (배쉬는 맞는 파일이 없으면 와일드카드를 글자 그대로 ls에 넘기기 때문에 이런 메시지가 나옵니다. 맥의 zsh에서는 no matches found라는 메시지가 나옵니다.) 그래서 ?는 무시할 글자 수를 정확히 알 때 씁니다. 여기서는 모든 파일 이름이 2004-XX-XX.json 모양이라는 것을 알기 때문에 마지막 두 자리를 ??로 바꾼 것입니다.

*: 아무 글자나 몇 개든

글자 수가 중요하지 않고 2004-01-로 시작하기만 하면 된다면 *를 씁니다. *는 아무 글자나 몇 개든(0개 포함) 대신합니다. 결과는 위의 ??와 같습니다.

ls 2004-01-*
2004-01-01.json  2004-01-09.json  2004-01-19.json  2004-01-27.json
2004-01-02.json  2004-01-12.json  2004-01-20.json  2004-01-28.json
2004-01-05.json  2004-01-13.json  2004-01-21.json  2004-01-29.json
2004-01-06.json  2004-01-14.json  2004-01-22.json  2004-01-30.json
2004-01-07.json  2004-01-15.json  2004-01-23.json
2004-01-08.json  2004-01-16.json  2004-01-26.json

*와 ?는 맨 뒤에만 쓸 수 있는 것이 아니라, 앞이든 중간이든 어디에나 쓸 수 있습니다. 예를 들어 다음과 같이 쓰면 매달 1일의 데이터만 골라낼 수 있습니다. (1일이 주말인 달은 방송이 없어서 빠져 있습니다.)

ls 2004-*-01.json
2004-01-01.json  2004-06-01.json  2004-10-01.json
2004-03-01.json  2004-07-01.json  2004-11-01.json
2004-04-01.json  2004-09-01.json  2004-12-01.json

[ ]: 이 중 한 글자

*나 ?는 그 자리에 무엇이 오든 다 가져옵니다. 그 자리에 특정 글자가 온 것만 가져오고 싶다면 대괄호 [ ]를 씁니다. 예를 들어 1월, 2월, 4월의 15일 데이터만 가져오려면 다음과 같이 씁니다.

ls 2004-0[124]-15.json
2004-01-15.json  2004-04-15.json

2004-0X-15.json의 X 자리에 1, 2, 4 중 하나가 오는 파일을 모두 가져옵니다. 헷갈리면 안 되는 점은, [124]가 124라는 세 글자를 찾는 것이 아니라, 한 글자 자리에 1이나 2나 4 중 하나가 오는지를 본다는 것입니다.

여기서 흔히 하는 실수가 [1,2,4]처럼 쉼표를 넣는 것입니다. 배쉬는 대괄호 안의 모든 글자를 후보로 보기 때문에, 이렇게 쓰면 1, 2, 4 말고 쉼표 ,가 그 자리에 오는 파일도 가져옵니다. 지금은 이름에 쉼표가 들어간 파일이 없어서 결과가 같지만, 의도와는 다른 패턴이니 쉼표 없이 쓰는 것이 바른 방법입니다.

대괄호 안에는 -로 범위를 적을 수도 있습니다. 예를 들어 1월부터 5월까지의 10일에서 12일 사이 데이터는 다음과 같이 고를 수 있습니다.

ls 2004-0[1-5]-1[0-2].json
2004-01-12.json  2004-02-12.json  2004-03-12.json  2004-05-11.json
2004-02-10.json  2004-03-10.json  2004-04-12.json  2004-05-12.json
2004-02-11.json  2004-03-11.json  2004-05-10.json

범위 앞에 !를 붙이면 그 범위를 뺀 나머지를 가져옵니다. 월의 첫 자리가 0인 01월부터 09월 가운데 1월부터 5월까지를 빼면 6월부터 9월까지만 남으니, 다음은 6월부터 9월까지의 1일과 2일 데이터입니다.

ls 2004-0[!1-5]-0[12].json
2004-06-01.json  2004-07-01.json  2004-08-02.json  2004-09-02.json
2004-06-02.json  2004-07-02.json  2004-09-01.json

{ }: 이 문자열들 중 하나

대괄호는 딱 한 글자 자리만 다룹니다. 두 글자 이상인 문자열 중 하나를 고르고 싶다면 중괄호 { }를 쓰고, 후보 문자열들을 쉼표로 구분합니다. 예를 들어 1월과 12월의 10일대 데이터만 보려면 다음과 같이 씁니다. 중괄호 안팎에 ?나 *를 함께 쓸 수도 있습니다.

ls 2004-{01,12}-1?.json
2004-01-12.json  2004-01-15.json  2004-12-10.json  2004-12-15.json
2004-01-13.json  2004-01-16.json  2004-12-13.json  2004-12-16.json
2004-01-14.json  2004-01-19.json  2004-12-14.json  2004-12-17.json

중괄호는 사실 와일드카드와 조금 다르게 동작합니다. 와일드카드는 있는 파일 중에서 맞는 것을 찾지만, 중괄호는 파일이 있든 없든 적힌 대로 문자열을 만들어 냅니다. 그래서 쉼표가 없는 2004-0{124}-15.json은 아무것도 펼쳐지지 않고 글자 그대로 남아서, 그런 이름의 파일이 없다는 오류가 납니다.

ls 2004-0{124}-15.json
ls: cannot access '2004-0{124}-15.json': No such file or directory

중괄호가 문자열을 만들어 낸다는 것은 echo로 확인해 볼 수 있습니다.

echo report-{2023,2024,2025}.csv
report-2023.csv report-2024.csv report-2025.csv

몇 개만 보기, 세어 보기: head, tail, wc

파일이 너무 많으니 앞의 5개만 보고 싶다면 다음과 같이 합니다.

ls *.json | head -n 5
2004-01-01.json
2004-01-02.json
2004-01-05.json
2004-01-06.json
2004-01-07.json

먼저 ls로 .json 파일 목록을 출력하고, 그것을 파이프로 head에 넘겼습니다. head는 말 그대로 앞부분(머리)을 보여 주는 명령어이고, -n 옵션으로 몇 줄을 볼지 정합니다. 반대로 tail -n 5는 맨 뒤의 5개를 보여 줍니다.

ls *.json | tail -n 5
2004-12-27.json
2004-12-28.json
2004-12-29.json
2004-12-30.json
2004-12-31.json

3.2에서 본 wc -l(줄 수만 세는 옵션)로 넘기면, 파일이 모두 몇 개인지 셀 수 있습니다. 2004년에 방송이 있었던 날이 262일이라는 뜻입니다.

ls *.json | wc -l
262

중괄호 하나가 문제 하나의 정보를 담고 있는데, 이대로는 배쉬로 다루기 좋은 모양이 아닙니다. 배쉬는 기본적으로 한 줄씩 데이터를 처리하는데, 이 파일은 문제 하나가 여러 줄에 걸쳐 있기 때문입니다. 그래서 문제 하나를 한 줄로 펼쳐 줄 필요가 있습니다.

문제 하나를 한 줄로: sed

3.2에서 본 sed로 이 작업을 할 수 있습니다. 명령어가 길어서, 3.3에서 배운 대로 sed의 규칙을 flat이라는 변수에 담아 두고 쓰겠습니다.

flat=':a; N; $!ba; s/\n//g; s/  */ /g; s/}, *{/},\n{/g; s/^\[ *//; s/ *\]$//'
sed "$flat" 2004-01-15.json | head -n 5

{ "category": "LITERATURE", "air_date": "2004-01-15", "question": "Sample clue #2015", "value": "$400", "answer": "answer 2015", "round": "Jeopardy!", "show_number": "4474" },
{ "category": "LITERATURE", "air_date": "2004-01-15", "question": "Sample clue #2016", "value": "$600", "answer": "answer 2016", "round": "Jeopardy!", "show_number": "4474" },
{ "category": "LITERATURE", "air_date": "2004-01-15", "question": "Sample clue #2017", "value": "$800", "answer": "answer 2017", "round": "Jeopardy!", "show_number": "4474" },
{ "category": "LITERATURE", "air_date": "2004-01-15", "question": "Sample clue #2018", "value": "$1000", "answer": "answer 2018", "round": "Jeopardy!", "show_number": "4474" },

이제 한 줄에 문제 하나가 들어갔습니다. 명령어가 괴상하게 생겼지요? 걱정하지 않아도 됩니다. 여러 번 말했듯이 이런 명령어를 외울 필요는 없고, 이런 건 검색하거나 AI에게 물어서 만들면 됩니다. 다만 무슨 일을 하는지 정도는 읽을 수 있으면 좋으니, ;로 구분된 규칙을 하나씩 보겠습니다.

  1. :a; N; $!ba: 파일의 모든 줄을 하나로 이어 붙여 메모리에 올립니다. (a라는 표시를 해 두고, 다음 줄을 붙이고, 마지막 줄이 아니면 a로 돌아가기를 반복합니다.)
  2. s/\n//g: 줄바꿈 문자를 모두 없앱니다. 이제 파일 전체가 한 줄입니다.
  3. s/ */ /g: 연달아 있는 공백을 공백 하나로 줄입니다.
  4. s/}, *{/},\n{/g: 문제와 문제 사이의 },과 { 사이에 줄바꿈을 넣습니다. 이렇게 문제마다 줄이 나뉩니다.
  5. s/^\[ *//; s/ *\]$//: 맨 앞의 [와 맨 뒤의 ]를 지웁니다.

그런데 1번 규칙이 하는 일을 보면, 이 명령어는 사실 3.2에서 말한 스트림 방식이 아니라 파일 전체를 메모리에 올리고 있습니다. 파일 하나가 몇십 KB 정도로 작으니 괜찮은 것이고, 50GB짜리 파일 하나에 이런 명령을 쓰면 메모리가 버티지 못합니다. 큰 파일을 날짜별로 잘게 나눠 두는 것에는 이런 이유도 있습니다.

Note맥을 쓴다면

맥의 sed는 리눅스(그리고 깃 배쉬와 Termux)의 GNU sed와 출신이 달라서, 위 명령어가 오류를 내거나 다르게 동작합니다. brew install gnu-sed로 GNU sed를 설치한 뒤 sed 대신 gsed를 쓰면 이 글의 명령어를 그대로 쓸 수 있습니다. 또는 JSON 전용 도구인 jq가 있다면 jq -c '.[]' 2004-01-15.json으로 같은 일을 훨씬 간단하게 할 수 있습니다. 실제로 JSON을 다룰 때는 jq처럼 그 형식을 이해하는 도구를 쓰는 편이 더 안전합니다.

원하는 줄만 골라내기: grep

이 퀴즈쇼의 문제들은 상금이 다 다른데, 2,000달러짜리 문제만 모아 보고 싶다고 해 보겠습니다. 문제 하나가 한 줄이 되었으니, 이제 3.2의 grep으로 "value": "$2000"이 들어간 줄만 골라내면 됩니다.

sed "$flat" 2004-01-15.json | grep '"value": "\$2000"'
{ "category": "ART", "air_date": "2004-01-15", "question": "Sample clue #2048", "value": "$2000", "answer": "answer 2048", "round": "Double Jeopardy!", "show_number": "4474" },
{ "category": "POTENT POTABLES", "air_date": "2004-01-15", "question": "Sample clue #2053", "value": "$2000", "answer": "answer 2053", "round": "Double Jeopardy!", "show_number": "4474" },
{ "category": "BUSINESS", "air_date": "2004-01-15", "question": "Sample clue #2058", "value": "$2000", "answer": "answer 2058", "round": "Double Jeopardy!", "show_number": "4474" },
{ "category": "OPERA", "air_date": "2004-01-15", "question": "Sample clue #2063", "value": "$2000", "answer": "answer 2063", "round": "Double Jeopardy!", "show_number": "4474" },
{ "category": "FOOD", "air_date": "2004-01-15", "question": "Sample clue #2068", "value": "$2000", "answer": "answer 2068", "round": "Double Jeopardy!", "show_number": "4474" },
{ "category": "U.S. CITIES", "air_date": "2004-01-15", "question": "Sample clue #2073", "value": "$2000", "answer": "answer 2073", "round": "Double Jeopardy!", "show_number": "4474" },

패턴 안의 $ 앞에 \를 붙인 이유는, grep의 패턴에서 $가 “줄의 끝”이라는 특별한 뜻으로 쓰이기 때문입니다. \$라고 쓰면 특별한 뜻 없이 글자 $ 그대로를 찾습니다. 그리고 2,000달러 문제는 Double Jeopardy! 라운드에만 있다는 것도 눈에 들어옵니다. 몇 문제인지는 다시 wc -l로 넘겨서 세면 됩니다.

sed "$flat" 2004-01-15.json | grep '"value": "\$2000"' | wc -l
6

2004년 1월 15일 방송에는 2,000달러짜리 문제가 6개 있었습니다.

모든 파일에 한꺼번에: xargs

그러면 2004년 전체에는 2,000달러 문제가 몇 개 있었을까요? 같은 작업을 2004-01-15.json 하나가 아니라 모든 .json 파일에 하면 됩니다. 이때 xargs를 씁니다.

ls *.json | xargs -n 1 sed "$flat" | grep '"value": "\$2000"' | wc -l
1572

먼저 ls로 .json 파일 이름들을 출력하고, 이것을 xargs에 넘깁니다. xargs는 입력으로 받은 텍스트를 다음 명령어의 인자로 바꿔서 그 명령어를 실행해 줍니다. 그냥 파이프로 넘기면 sed는 파일 이름이 적힌 텍스트 자체를 가공해 버리지만, xargs를 거치면 sed 2004-01-01.json처럼 파일 이름을 인자로 받아서 그 파일의 내용을 가공합니다. 그리고 -n 1은 파일을 한 번에 하나씩 넘겨서 sed를 파일마다 따로 실행하라는 뜻입니다.

-n 1이 왜 필요한지 확인해 보겠습니다. sed는 파일을 여러 개 받으면 이것들을 하나의 긴 스트림으로 이어서 처리합니다. 그러면 1번 규칙이 모든 파일을 한 줄로 이어 붙이고, 어떤 파일의 마지막 문제와 다음 파일의 첫 문제 사이에는 }, 대신 파일의 끝과 시작을 뜻하는 ][가 끼어 있기 때문에 4번 규칙에 걸리지 않아 줄이 나뉘지 않습니다. 전체 문제 수를 세어 보면 차이가 드러납니다.

ls *.json | xargs -n 1 sed "$flat" | wc -l
ls *.json | xargs sed "$flat" | wc -l
15982
15721

-n 1을 쓰면 262개 방송의 61문제씩, 모두 15,982개의 줄이 나옵니다. -n 1을 빼면 파일과 파일 사이의 261곳에서 두 문제가 한 줄에 붙어 버려서, 15,982 − 261 = 15,721줄이 됩니다. 위의 2,000달러 문제 수는 우연히 이 실수의 영향을 받지 않지만(파일의 첫 문제와 마지막 문제가 2,000달러 문제가 아니라서), 이런 실수는 오류 메시지 없이 결과만 조용히 틀리게 만들기 때문에 더 위험합니다. 명령어를 AI에게 받아 쓸 때도 이렇게 결과가 상식과 맞는지 한 번씩 확인하는 습관이 중요합니다.

결과 저장하고 정리하기: >, rm, mv

2,000달러 문제만 모아서 파일로 저장하고 싶다면 3.2의 리다이렉션 >를 씁니다. 그런데 지금 보고 있는 폴더는 데이터 파일로 가득하니, 결과는 한 단계 위의 폴더에 저장하겠습니다.

ls *.json | xargs -n 1 sed "$flat" | grep '"value": "\$2000"' > ../2000.json
head -n 3 ../2000.json
{ "category": "WORLD GEOGRAPHY", "air_date": "2004-01-01", "question": "Sample clue #1438", "value": "$2000", "answer": "answer 1438", "round": "Double Jeopardy!", "show_number": "4464" },
{ "category": "MATH", "air_date": "2004-01-01", "question": "Sample clue #1443", "value": "$2000", "answer": "answer 1443", "round": "Double Jeopardy!", "show_number": "4464" },
{ "category": "SPORTS", "air_date": "2004-01-01", "question": "Sample clue #1448", "value": "$2000", "answer": "answer 1448", "round": "Double Jeopardy!", "show_number": "4464" },

3.1에서 본 것처럼 ..은 한 단계 위의 폴더, .은 지금 폴더입니다. 그래서 ./2000.json(또는 그냥 2000.json)이라고 쓰면 지금 폴더에 저장되고, ../2000.json이라고 써야 위의 폴더에 저장됩니다. 저장된 파일을 볼 때도 마찬가지로 ../2000.json이라고 써야 합니다. head로 확인해 보니 2,000달러 문제만 들어 있습니다. head는 앞부분만 보는 명령어라서, 파일 전체를 보고 싶다면 cat ../2000.json을 쓰면 됩니다.

파일을 다른 폴더로 옮기려면 mv(move)를, 지우려면 rm(remove)을 씁니다. 먼저 위의 폴더에 results라는 폴더를 만들고(mkdir, make directory), 거기로 옮겨 보겠습니다.

mkdir -p ../results
mv ../2000.json ../results/
ls ../results
2000.json

mv 원래경로 옮길폴더처럼 쓰고, mv 옛이름 새이름처럼 쓰면 파일 이름을 바꾸는 데에도 쓸 수 있습니다. 이제 이 파일을 지워 보겠습니다.

rm ../results/2000.json
ls ../results

폴더가 비었으니 ls는 아무것도 출력하지 않습니다.

rm으로 지운 파일은 휴지통으로 가지 않고 바로 사라집니다. 되돌릴 수 없으니, 특히 * 같은 와일드카드와 함께 쓸 때는 지울 파일이 맞는지 먼저 ls로 확인하는 습관을 들이세요.

스크립트로 상금별로 모으기

지금까지는 2,000달러 문제만 모았는데, 상금마다 모두 이렇게 모으고 싶다면 드디어 3.3의 스크립트가 필요합니다. 그 전에, 데이터에 어떤 상금이 있는지부터 알아야 합니다. grep -o는 줄 전체가 아니라 패턴에 맞는 부분만 뽑아 줍니다. 이것을 sort로 정렬한 뒤 uniq -c로 넘기면, 같은 값이 몇 번 나왔는지 셀 수 있습니다.

ls *.json | xargs -n 1 sed "$flat" | grep -o '"value": [^,]*' | sort | uniq -c
   1572 "value": "$1000"
   1572 "value": "$1200"
   1572 "value": "$1600"
   1572 "value": "$200"
   1572 "value": "$2000"
   3144 "value": "$400"
   1572 "value": "$600"
   3144 "value": "$800"
    262 "value": null

uniq는 바로 이웃한 같은 줄들을 하나로 합치는 명령어라서, 같은 값끼리 모이도록 먼저 sort로 정렬해 두어야 합니다. -c(count)는 합치면서 몇 줄이었는지를 함께 출력하라는 옵션입니다. sort | uniq -c는 빈도를 셀 때 아주 자주 쓰는 조합이니 기억해 두면 좋습니다. 결과를 보면 상금은 200, 400, 600, 800, 1000, 1200, 1600, 2000달러 여덟 가지가 있고, Final Jeopardy! 문제는 null입니다.

이제 이 여덟 가지 상금마다 문제를 모아 파일로 저장하는 반복문을 짭니다.

for val in 200 400 600 800 1000 1200 1600 2000; do
    echo "Processing ${val}..."
    ls *.json | xargs -n 1 sed "$flat" | grep -F "\"value\": \"\$${val}\"" > "../${val}.json"
    # grep이 하나라도 찾았는지(종료 코드가 0인지) 확인합니다.
    if [ "${PIPESTATUS[2]}" = "0" ]; then
        echo "${val} done"
    fi
done
Processing 200...
200 done
Processing 400...
400 done
Processing 600...
600 done
Processing 800...
800 done
Processing 1000...
1000 done
Processing 1200...
1200 done
Processing 1600...
1600 done
Processing 2000...
2000 done

몇 군데를 짚어 보겠습니다.

  • grep -F는 패턴을 특별한 뜻 없이 글자 그대로 찾으라는 옵션입니다. 그래서 $에 \를 붙일 필요가 없습니다.
  • 대신 패턴을 작은따옴표가 아니라 큰따옴표로 감쌌습니다. 작은따옴표 안에서는 ${val} 같은 변수가 펼쳐지지 않기 때문입니다. 큰따옴표 안에서 글자 "를 쓰려면 \"로, 글자 $를 쓰려면 \$로 적습니다. 그래서 "\"value\": \"\$${val}\""은 val이 200일 때 "value": "$200"이라는 패턴이 됩니다. 패턴 끝에 닫는 따옴표까지 넣었기 때문에, 200달러를 찾을 때 2000달러 문제가 섞여 들어오지 않습니다.
  • PIPESTATUS는 바로 전 파이프라인에 있던 명령어들의 종료 코드를 차례로 담고 있는 배쉬의 특별한 변수입니다. 0번이 ls, 1번이 xargs, 2번이 grep이니, ${PIPESTATUS[2]}가 0이면 grep이 맞는 줄을 하나 이상 찾았다는 뜻입니다.

위의 폴더를 확인해 보면, 상금별로 파일이 생겼습니다. 각 파일이 몇 줄인지, 즉 상금별로 문제가 몇 개인지도 wc -l로 한 번에 볼 수 있습니다.

wc -l ../*.json
   1572 ../1000.json
   1572 ../1200.json
   1572 ../1600.json
   1572 ../200.json
   1572 ../2000.json
   3144 ../400.json
   1572 ../600.json
   3144 ../800.json
  15720 total

상금별로 더 들여다보기

이렇게 상금별로 나눈 파일에서는, 같은 방법으로 상금마다 어떤 카테고리가 자주 나왔는지, 어느 라운드에 나왔는지 등을 볼 수 있습니다. 예를 들어 400달러 문제가 어느 라운드에 나왔는지 세어 보겠습니다.

grep -o '"round": "[^"]*"' ../400.json | sort | uniq -c
   1572 "round": "Double Jeopardy!"
   1572 "round": "Jeopardy!"

400달러 문제는 Jeopardy! 라운드(두 번째 문제)와 Double Jeopardy! 라운드(첫 번째 문제)에 모두 있습니다. 2,000달러 문제의 카테고리 가운데 많이 나온 5개를 보려면, uniq -c의 결과를 다시 sort -rn(숫자로, 큰 것부터)으로 정렬하고 head로 자릅니다.

grep -o '"category": "[^"]*"' ../2000.json | sort | uniq -c | sort -rn | head -n 5
    114 "category": "SPORTS"
    114 "category": "SCIENCE"
    113 "category": "POTENT POTABLES"
    106 "category": "WORD ORIGINS"
    103 "category": "OPERA"

(연습 데이터는 카테고리를 무작위로 넣었기 때문에 빈도가 고르게 나옵니다. 원본 데이터로 해 보면 실제 방송에서 어떤 카테고리가 자주 나왔는지 볼 수 있습니다.) 비슷한 방법으로 상금이 아니라 카테고리별, 라운드별로 문제를 모아서 분석할 수도 있습니다.

정리

우리가 다룬 2004년 데이터는 원본의 아주 일부입니다. 원본은 수십 년 치 방송이 쌓여 있어서, 이런 단순한 작업도 시간이 꽤 걸립니다. 그래서 실제로는 이렇게 배쉬로 1차 탐색을 하면서 데이터의 구조를 파악하고 필요한 부분을 골라낸 다음, 골라낸 데이터를 파이썬 같은 언어로 가져가서 2장에서 본 것처럼 본격적으로 요약하고 시각화합니다.

  • tar -xzf로 압축을 풀고, ls -la로 파일의 권한과 크기를 확인합니다. 자주 쓰는 명령어는 alias로 줄여 씁니다.
  • 와일드카드 ?(한 글자), *(아무 글자나 몇 개든), [ ](이 중 한 글자, -로 범위, !로 제외)와 중괄호 { }(이 문자열들 중 하나)로 파일을 고릅니다.
  • head, tail, wc -l로 일부만 보거나 세고, cat과 less로 파일을 엽니다.
  • sed로 데이터를 다루기 좋은 모양으로 바꾸고, grep으로 원하는 줄만 골라냅니다.
  • xargs로 여러 파일에 같은 명령을 적용하고, sort | uniq -c로 빈도를 셉니다.
  • 반복문 스크립트로 같은 작업을 여러 조건에 대해 한 번에 처리합니다.

그런데 이렇게 명령어와 스크립트를 쓰다 보면, 몇 달 뒤의 나나 다른 사람이 이 코드를 다시 읽고 그대로 다시 실행할 수 있을지가 걱정되기 시작합니다. 다음 글부터는 이 질문, 즉 좋은 코드란 무엇이고 어떻게 남겨야 하는지를 다룹니다.
