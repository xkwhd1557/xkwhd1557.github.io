1.1 빅데이터의 3V와 데이터의 구조

1장 데이터 사이언스의 기초 · 데이터는 왜 다루기 어려울까요?

데이터 사이언스·AI
데이터 사이언스 개론
데이터를 다루기 어렵게 만드는 빅데이터의 3V(속도·크기·다양성)를 예와 함께 살펴보고, 정형·반정형·준정형·비정형 데이터가 어떻게 다른지 파이썬 예제로 비교합니다.
Published

November 2, 2026

들어가며

지난 글에서는 데이터 사이언스가 통계에서 출발해 컴퓨터와 함께 자라 왔다는 이야기를 했습니다. 데이터가 스스로 말하게 한다는 철학 자체는 어렵지 않게 이해되실 겁니다. 그렇다면 이제 데이터를 어떻게 다룰지를 이야기해야 합니다. 아쉽게도 이것은 생각만큼 쉽지 않습니다.

이번 글에서는 먼저 데이터를 다루기 어렵게 만드는 세 가지 특성인 빅데이터의 3V를 살펴보고, 그 어려움을 줄이기 위해 데이터를 구조에 따라 네 가지로 나누는 방법을 파이썬 예제와 함께 알아보겠습니다.

빅데이터의 3V

데이터를 다루기 어렵게 만드는 요인은 흔히 빅데이터의 3V로 요약됩니다. 이 표현은 2001년 정보기술 분석가 레이니(D. Laney)가 쓴 짧은 보고서에서 처음 등장한 뒤 널리 퍼졌습니다.1

Note정의 1.1.1 (빅데이터의 3V)

데이터를 다루기 어렵게 만드는 다음 세 가지 특성을 빅데이터의 3V라고 합니다.

  • 속도(velocity): 데이터가 생겨나는 속도와, 그 데이터가 가치를 잃기 전에 수집·가공·분석을 마쳐야 하는 속도가 매우 빠릅니다.
  • 크기(volume): 데이터의 양이 너무 많아서 일반적인 소프트웨어나 한 대의 컴퓨터로는 저장하고 분석하기 어렵습니다.
  • 다양성(variety): 데이터의 형태가 숫자, 문장, 이미지, 음성 등으로 매우 다양하고, 한 데이터 안에도 여러 형태가 섞여 있습니다.

하나씩 예를 들어 살펴보겠습니다.

속도. 대표적인 예가 자율주행 자동차입니다. 자율주행 차를 타고 가는 동안 인공지능은 차가 달리는 속도에 맞춰 판단을 내려야 합니다. 다음 교차로에서 좌회전할지 우회전할지를 5분, 10분씩 고민할 여유가 없습니다. 목적지, 현재 교통 상황, 주변 차량과 보행자 같은 데이터를 순식간에 모으고 처리해 판단을 끝내야 합니다. 이처럼 목적에 따라 데이터를 수집하고 처리해야 하는 마감 시간이 아주 짧은 경우가 많기 때문에, 데이터 처리 과정 자체가 매우 빨라야 합니다.

크기. 말 그대로 데이터가 너무 방대하다는 뜻입니다. 2019년 유튜브가 밝힌 바에 따르면, 유튜브에는 1분마다 500시간이 넘는 분량의 영상이 올라옵니다.2 만약 모든 유튜브 영상에 인공지능으로 자막을 자동 생성하는 기능을 붙인다면, 우리는 매 분 500시간이 넘는 영상을 처리해야 하는 셈입니다. 이를 감당하려면 효율적인 알고리즘은 물론이고, 그 알고리즘으로 방대한 데이터를 실제로 처리할 수 있는 인프라가 필요합니다.

또 다른 예로, 유럽 입자물리연구소(CERN)의 거대 강입자 충돌기(Large Hadron Collider, LHC)에 설치된 검출기 가운데 하나인 LHCb에서만 초당 약 4테라바이트의 데이터가 쏟아져 나옵니다.3 이 엄청난 양을 전부 저장하는 것은 불가능하기 때문에, 의미 있는 충돌 사건만 실시간으로 골라내는 방법을 설계하는 것 자체가 하나의 거대한 과제가 됩니다. 크기와 속도의 어려움이 한꺼번에 몰려오는 셈입니다.

다양성. 데이터 사이언스가 다루는 데이터는 대개 깔끔하게 정리된 형태가 아니라, 문장, 숫자, 이미지, 음성처럼 온갖 형태를 띱니다. 특히 하나의 데이터가 여러 형태의 부분 데이터로 이루어진 경우도 있습니다.

한 사람의 진료 기록을 떠올려 보겠습니다. 진료 기록에는 환자의 인적 사항이 글자로 적혀 있을 것이고, 엑스레이를 찍었다면 이미지 데이터가, 혈액 검사를 했다면 백혈구 수나 중성지방 수치 같은 값이 표 형태로 들어 있을 것입니다. 하나의 진료 기록 안에 서로 다른 형태의 데이터가 함께 들어 있는 것입니다.

그럼 부분 데이터를 하나씩 따로 다루면 되지 않느냐고 생각하실 수 있습니다. 하지만 의사는 부분 데이터를 따로따로 보고 진단을 내리지 않습니다. 모든 정보를 종합해서 치료 방향을 결정합니다. 중간 과정에서는 부분 데이터를 각각 다룰 수 있어도, 마지막에는 전체를 아우르는 결과를 내야 합니다. 데이터 사이언티스트는 이렇게 다양한 데이터를 하나로 엮어 의사가 합리적인 결정을 내릴 수 있도록 도와야 하는데, 이것은 말처럼 쉬운 일이 아닙니다.

구조에 따른 데이터의 분류

데이터 사이언티스트들은 이런 어려움을 조금이라도 줄일 방법을 찾아 왔습니다. 그중 하나가 3V의 ’다양성’에 대한 관찰입니다. 데이터의 형태가 다양하더라도, 데이터가 일정한 구조를 갖추고 있을수록 처리하기 쉬워지고, 구조 없이 자유분방할수록 처리하기 어려워집니다. 그래서 데이터를 얼마나 정돈되어 있는지에 따라 다음 네 가지로 나누곤 합니다.4

분류 영어 대표적인 예
정형 데이터 structured data 엑셀 표, 데이터베이스 테이블
반정형 데이터 semi-structured data XML, JSON 파일
준정형 데이터 quasi-structured data 프로그램 로그, 웹 클릭 기록
비정형 데이터 unstructured data 웹 페이지, 이미지, 음성, 손글씨

위에서 아래로 갈수록 구조가 느슨해지고, 컴퓨터가 다루기도 어려워집니다. 반면 양은 점점 많아지고 복잡해집니다. 각각이 어떤 데이터인지, 그리고 컴퓨터가 이 데이터를 읽을 때 무엇이 달라지는지 순서대로 살펴보겠습니다.

Note정의 1.1.2 (정형 데이터)

행과 열처럼 미리 정해진 틀이 있고, 각 칸에 들어가는 값의 종류(이름, 날짜, 금액 등)도 정해져 있는 데이터를 정형 데이터(structured data) 또는 구조화된 데이터라고 합니다.

대표적인 예가 엑셀 같은 스프레드시트에 저장하는 표입니다. 표에서는 행과 열에 따라 칸이 정해져 있고, 각 칸에는 이름, 날짜, 주소, 금액처럼 대부분 글자나 숫자가 들어갑니다. 사람이 이해하기 쉬운 만큼, 컴퓨터에게 처리 방법을 알려 주는 것도 아주 간단합니다. 예를 들어 다음과 같은 표가 있다면, 파이썬의 판다스(pandas)로 읽어서 열 하나의 평균을 내는 데 몇 줄이면 충분합니다.

import io
import pandas as pd

csv_text = """환자번호,이름,방문일,공복혈당
1557,박종우,2026-04-06,126
2400,김찬호,2026-04-07,98
88848,손인욱,2026-04-07,105
"""

df = pd.read_csv(io.StringIO(csv_text))
print(df)
print("평균 공복혈당:", round(df["공복혈당"].mean(), 1))
   환자번호   이름         방문일  공복혈당
0  1557  박종우  2026-04-06   126
1  2400  김찬호  2026-04-07    98
2  88848  손인욱  2026-04-07   105
평균 공복혈당: 109.7

“공복혈당”이라는 열 이름만 알려 주면 컴퓨터는 그 열의 값이 어디에 있는지 정확히 압니다. 틀이 정해져 있다는 것은 바로 이런 뜻입니다.

Note정의 1.1.3 (반정형 데이터)

표처럼 고정된 틀은 없지만, 데이터 안에 각 부분이 무엇인지 알려 주는 표시(예: 태그)가 들어 있는 데이터를 반정형 데이터(semi-structured data) 또는 반구조화된 데이터라고 합니다.

대표적인 예가 XML 파일입니다. XML이 낯선 분들을 위해 앞의 진료 기록을 XML로 적어 보겠습니다.

<?xml version="1.0" encoding="UTF-8"?>
<PatientRecord>
    <PatientID>1557</PatientID>
    <Name>박종우</Name>
    <VisitDate>2026-04-06</VisitDate>
    
    <Diagnosis>
        <Code>E11</Code>
        <Description>제2형 당뇨병</Description>
    </Diagnosis>

    <TestResults>
        <Test type="Blood">
            <Item>Glucose</Item>
            <Value unit="mg/dL">126</Value>
        </Test>
        <Test type="Vitals">
            <Item>BloodPressure</Item>
            <Value unit="mmHg">130/85</Value>
        </Test>
    </TestResults>

    <DoctorNote>
        환자는 최근 피로감을 호소함. 식단 조절 및 운동 권고함.
    </DoctorNote>
</PatientRecord>

XML은 데이터 내부의 구조를 알려 주는 도구로 태그(tag)를 씁니다. < > 안에 들어 있는 것들이 태그이고, 각 태그는 부분 데이터의 이름표 역할을 합니다. XML 문법을 몰라도 태그 이름만 보면 이것이 환자의 진료 기록(PatientRecord)이고, 그 안에 환자 번호(PatientID), 이름(Name) 같은 정보가 들어 있다는 것을 짐작할 수 있습니다.

컴퓨터도 이를 마찬가지로 짐작하여 구분여 행과 열의 좌표가 아니더라도, 태그같이 구조를 파악할 수 있는 이름표가 있다면 원하는 값을 찾아갑니다.

import xml.etree.ElementTree as ET

# xml_text에는 위의 XML 문서 전체가 문자열로 들어 있습니다.
# 첫 줄에 인코딩 선언이 있으므로 바이트로 바꿔서 읽습니다.
root = ET.fromstring(xml_text.encode("utf-8"))
print("이름:", root.find("Name").text)
for test in root.iter("Test"):
    value = test.find("Value")
    print(test.find("Item").text, "=", value.text, value.get("unit"))
이름: 박종우
Glucose = 126 mg/dL
BloodPressure = 130/85 mmHg

반정형 데이터는 표만큼 틀이 단단하지는 않지만, 태그처럼 내부 구조를 알려 주는 장치가 있어서 컴퓨터가 다루기에 그리 까다롭지 않습니다. 대신 유연성이 있다는 점을 고려해야 합니다. 예를 들어 어떤 진료 기록에는 <TelNumber> 같은 태그가 추가로 들어 있을 수도 있고, 검사 결과(<Test>)가 몇 개 들어 있을지도 기록마다 다릅니다. 행과 열이 정해진 표와 달리 이런 차이를 감안해서 처리해야 하는데, 이 유연성은 장점이자 단점입니다.

Note정의 1.1.4 (준정형 데이터)

어느 정도 반복되는 형식은 있지만, 그 형식이 명시적으로 정해져 있지 않고 만든 사람이나 상황에 따라 제각각인 데이터를 준정형 데이터(quasi-structured data) 또는 준구조화된 데이터라고 합니다.

준정형 데이터는 조금 애매한 친구입니다. 반정형 데이터처럼 친절한 이름표는 없지만, 그렇다고 아무런 구조가 없다고 하기도 어렵습니다. 대표적인 예가 프로그램이 남기는 로그(log) 메시지입니다.

2026-04-20 00:24:00 [ERROR] User(ID:1557) login failed - Invalid Password / IP: 203.0.113.7

컴퓨터에서 이런 줄이 빼곡히 적힌 로그 파일을 보신 적이 있을 겁니다. 이런 메시지는 소설처럼 아무 형식 없이 쓰인 글은 아닙니다. 날짜, 시간, 사용자 번호, IP 주소를 적는다는 기본 틀이 보이니까요. 하지만 엑셀처럼 칸이 나뉘어 있지도 않고, XML처럼 태그가 붙어 있지도 않습니다. 그저 개발자가 “이런 상황에서는 이런 메시지를 남겨라”라고 정해 둔 규칙대로 찍혀 나온 결과물일 뿐입니다.

문제는 이 틀 자체가 개발자 마음대로라는 점입니다. 어떤 게임은 위와 같은 형식으로 로그를 남기더라도, 다른 게임은 전혀 다른 형식을 쓸 수 있습니다. 같은 프로그램 안에서도 모듈마다 형식이 다른 경우도 흔합니다. 그래서 준정형 데이터를 읽으려면, 사람이 직접 형식을 파악해서 컴퓨터에게 패턴을 알려 줘야 합니다. 파이썬에서는 보통 정규 표현식(regular expression)을 씁니다.(정규 표현식은 지금은 그냥 이런 준정형적 구문을 작성하기 위한 규칙 정도로 생각하시면 충분합니다.)

import re

logs = [
    "2026-04-20 00:24:00 [ERROR] User(ID:1557) login failed - Invalid Password / IP: 203.0.113.7",
    "2026-04-20 00:24:05 [INFO] User(ID:2042) login ok / IP: 198.51.100.23",
    "[20/Apr/2026:00:24:09] WARN uid=3310 too many attempts from 203.0.113.7",
]

pattern = re.compile(
    r"^(?P<date>\d{4}-\d{2}-\d{2}) (?P<time>\d{2}:\d{2}:\d{2}) "
    r"\[(?P<level>\w+)\] User\(ID:(?P<user>\d+)\).*IP: (?P<ip>[\d.]+)$"
)

for line in logs:
    m = pattern.match(line)
    if m:
        print(m.groupdict())
    else:
        print("읽지 못함:", line)
{'date': '2026-04-20', 'time': '00:24:00', 'level': 'ERROR', 'user': '1557', 'ip': '203.0.113.7'}
{'date': '2026-04-20', 'time': '00:24:05', 'level': 'INFO', 'user': '2042', 'ip': '198.51.100.23'}
읽지 못함: [20/Apr/2026:00:24:09] WARN uid=3310 too many attempts from 203.0.113.7

처음 두 줄은 우리가 알려 준 패턴과 형식이 같아서 잘 읽혔지만, 세 번째 줄은 같은 종류의 정보(시간, 사용자, IP)를 담고 있는데도 형식이 달라서 읽지 못했습니다. 준정형 데이터를 다룰 때는 이렇게 형식이 조금씩 다른 경우를 하나하나 찾아 처리해야 합니다. 엄청나게 까다롭다고까지 하기는 어렵지만, 데이터 사이언티스트의 품이 꽤 드는 작업입니다. 게다가 로그 같은 데이터는 기계가 쉬지 않고 쏟아내는 경우가 대부분이라서, 3V 가운데 크기와 속도 면에서는 아주 무시무시한 상대입니다.

Note정의 1.1.5 (비정형 데이터)

미리 정해진 틀이나 내부 구조를 알려 주는 표시가 없어서, 어떤 정보가 어디에 있는지 바로 알 수 없는 데이터를 비정형 데이터(unstructured data) 또는 비구조화된 데이터라고 합니다.

마지막으로 비정형 데이터는 세상 데이터의 대부분을 차지하는 녀석입니다. 쉬운 예가 인터넷입니다. 포털 사이트의 첫 화면을 열어 보면 뉴스, 쇼핑, 광고, 짧은 영상 등이 한데 뒤섞여 있습니다. 책을 스캔해 PDF로 만든다고 할 때도, 스캔되는 대상은 손글씨일 수도, 그림일 수도, 타자기로 친 글일 수도 있습니다. 이런 데이터에는 “무엇이 어디에 있고 그것이 무엇인지”를 알려 주는 정보가 전혀 없습니다.

앞의 진료 기록으로 비교해 보면 차이가 분명해집니다. 의사의 소견란에 “공복 혈당이 126으로 다소 높게 나왔으니 식단 조절이 필요해 보입니다”라고 자유롭게 적혀 있다면, 사람은 혈당 수치를 금방 찾아내지만 컴퓨터에게는 그저 글자의 나열일 뿐입니다. 여기서 “혈당 = 126”이라는 정보를 뽑아내려면 문장을 이해하는 훨씬 복잡한 알고리즘이 필요합니다.

하지만 동시에 비정형 데이터는 정보의 보고입니다. 의미 있는 정보의 상당 부분이 바로 이런 비정형 데이터 안에 있습니다. 인류의 지식을 데이터로 만들고 이를 바탕으로 중요한 결정을 내리고 싶다면, 이 거대한 정보 더미를 뒤져서 보석을 찾아내야 합니다. 그래서 데이터 사이언티스트는 비정형 데이터를 다룰 때 고도로 복잡한 알고리즘을 사용합니다. 흔히 말하는 딥러닝도 그중 하나입니다. 이미지에서 사물을 알아보고, 음성에서 단어를 뽑아내는 일이 모두 비정형 데이터를 처리하는 과정입니다. 비정형 데이터는 3V의 어려움을 빠짐없이 갖고 있기 때문에, 이를 얼마나 잘 다루느냐가 곧 데이터 사이언티스트의 실력을 가늠하는 척도가 되기도 합니다.

정리

  • 데이터는 속도, 크기, 다양성(3V) 때문에 다루기 어렵습니다. 실제 문제에서는 이 세 가지가 한꺼번에 몰려오는 경우가 많습니다.
  • 데이터는 구조가 얼마나 정돈되어 있는지에 따라 정형, 반정형, 준정형, 비정형 데이터로 나뉩니다. 구조가 느슨해질수록 컴퓨터에게 “어디에 무엇이 있는지”를 알려 주기 어려워지고, 그만큼 데이터 사이언티스트의 품이 더 듭니다.
  • 예제에서 보았듯이 정형 데이터는 열 이름만으로, 반정형 데이터는 태그로 원하는 값을 찾을 수 있습니다. 반면 준정형 데이터는 사람이 형식을 직접 파악해 알려 줘야 하고, 비정형 데이터는 문장이나 이미지 자체를 이해하는 알고리즘이 필요합니다.

이렇게 다루기 까다로운 데이터를, 데이터 사이언스는 실제로 어디에서 어떻게 쓰고 있을까요? 다음 글에서는 데이터 사이언스가 활약하는 여러 분야를 살펴보겠습니다.
