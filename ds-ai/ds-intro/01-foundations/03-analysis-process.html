1.3 데이터 분석의 과정

1장 데이터 사이언스의 기초 · 데이터 사이언티스트는 문제에 어떻게 접근할까요?

데이터 사이언스·AI
데이터 사이언스 개론
데이터 엔지니어링, 데이터 분석, 데이터 애널리틱스라는 데이터 사이언스의 세 갈래를 구분하고, 질문 설정부터 커뮤니케이션까지 데이터 분석의 다섯 단계와 그 단계를 굴러가게 하는 기대치의 순환을 예제와 함께 살펴봅니다.
Published

November 3, 2026

들어가며

지난 글까지는 데이터 사이언스가 어떤 학문이고, 어디에서 어떻게 쓰이며, 데이터 사이언티스트에게 어떤 소양이 필요한지를 살펴보았습니다. 이번 글에서는 한 걸음 더 들어가서, 데이터 사이언스 프로젝트가 실제로 대략 어떤 과정을 거쳐 진행되는지 이야기해 보겠습니다.

여기서 다루는 내용은 구체적인 수학이나 공학 기법이라기보다, 데이터 사이언티스트가 문제를 마주했을 때 어떤 순서로 생각하는지에 대한 이야기입니다. 단계의 이름이나 순서를 외울 필요는 전혀 없습니다. 전체적인 흐름을 따라가면서 “아, 이런 식으로 문제에 접근하는구나” 하는 감을 잡으시면 충분합니다.

데이터 사이언스의 세 갈래

데이터 사이언스를 한마디로 하면, 데이터를 수집하고, 정제하고, 이리저리 가공해서 어떤 결과물을 만들어 내는 학문입니다. 이 과정에서 어느 단계에 무게를 두느냐에 따라 데이터 사이언스는 흔히 세 갈래로 나뉩니다.

갈래 영어 주로 하는 일 무게중심
데이터 엔지니어링 data engineering 데이터를 수집·정제·저장하고 관리하는 기반을 만듦 컴퓨터 공학
데이터 분석 data analysis 이미 일어난 일을 분석해 왜 일어났는지 밝힘 수학·통계
데이터 애널리틱스 data analytics 과거의 패턴으로 앞으로 무엇이 일어날지 예측하고 대응 전략을 세움 그 중간

미리 말씀드리자면, 이 구분은 상당 부분 학술적인 구분입니다. 데이터가 핵심 사업인 대형 테크 기업이 아니라면, 실무에서는 세 가지가 잘 나뉘지 않는 경우가 많습니다. 현실에서는 “데이터 사이언티스트를 한 명 뽑았으니, 데이터에 관한 일은 전부 그 사람이 맡는다”가 되기 일쑤입니다.

데이터 엔지니어링

데이터 엔지니어링은 무엇보다 데이터를 수집하고, 가공하고, 관리하는 일입니다. 아무리 좋은 분석 기법이 있어도 쓸 만한 데이터가 없으면 소용이 없겠지요. 데이터 엔지니어링은 날것의 데이터를 모아서 분석가가 쓰기 좋은 형태로 정제하고 저장해, 데이터 사이언스가 활약할 수 있는 기반을 닦는 것을 목표로 합니다.

데이터는 보통 컴퓨터나 그와 비슷한 기계로 수집하고 관리하므로, 데이터 엔지니어링에서는 컴퓨터 공학 지식이 핵심입니다. 실제로 데이터 엔지니어링과 함께 떠오르는 키워드도 대용량 데이터 처리, 데이터베이스와 SQL, 클라우드 컴퓨팅, 쿼리 최적화처럼 대부분 컴퓨터 공학 쪽입니다.

데이터 분석

데이터 분석은 이렇게 준비된 데이터를 가지고, 수학과 통계 지식, 그리고 데이터 사이언스를 적용하려는 분야에 대한 이해를 총동원해서 데이터를 말 그대로 읽고 분석하는 일입니다. 보통은 이미 일어난 일(과거라고 해 봐야 지난달이나 작년 일인 경우가 많지만요)을 보고, 그 일이 왜 일어났는지에 대한 통찰을 끌어냅니다.

이를 위해서는 문제 상황을 정확히 파악해 추상화하고, 알맞은 도구로 모델링하는 능력이 필요합니다. 그래서 데이터 분석에서는 컴퓨터 공학 지식보다 수학적인 역량이 더 핵심이 됩니다. 문제에 등장하는 대상을 제대로 모델링하려면 해석학, 확률론, 기하학이나 위상수학이 필요하고, 그 모델에서 명제를 이끌어 내려면 통계학이나 함수해석학 같은 수학적 논리가 필요합니다. 결과를 실제로 확인하려면 최적화와, 그것을 컴퓨터에서 돌려 볼 수 있는 과학적 계산(scientific computing) 지식도 조금 필요합니다. (그렇다고 컴퓨터 공학이 필요 없다는 뜻은 아닙니다. 컴퓨터 공학적 방법론의 아이디어를 이해하고 있으면 큰 도움이 됩니다.) 데이터 분석과 함께 자주 나오는 키워드로는 탐색적 자료 분석, 통계적 검정, 데이터 시각화 등이 있습니다.

데이터 애널리틱스

데이터 애널리틱스는 이름부터 데이터 분석과 비슷해서 둘을 섞어 쓰는 경우도 많습니다. 실제로 목적도 비슷합니다. 다만 데이터 분석이 이미 일어난 일의 원인을 밝히는 데 집중한다면, 데이터 애널리틱스는 앞으로 어떤 일이 일어날지를 예측하고 그에 맞는 처방, 즉 대응 전략을 세우는 데 무게를 둡니다. 결국 그 바탕은 데이터 분석의 결과이므로 둘을 하나로 묶어 보는 사람도 있지만, 애널리틱스가 더 넓은 관점에서 예측과 처방에 초점을 맞춘다는 점에서 구분할 만한 의미가 있다고 생각합니다.

과거의 일을 바탕으로 미래를 예측하려면, 과거의 패턴을 알고리즘으로 만들어 미래에 일어날 일을 계산하는 시스템을 만들어야 합니다. 여기서 “과거의 패턴을 알고리즘으로 만드는 것”이 바로 흔히 말하는 학습입니다. 그래서 데이터 애널리틱스는 머신러닝, 컴퓨터 비전, 비즈니스 애널리틱스, 데이터 마이닝, 인공지능 같은 키워드로 유명한, 요즘 가장 뜨거운 분야이기도 합니다.

학습 이야기가 나온 김에 잠깐 짚고 넘어가겠습니다. 요즘은 ChatGPT, Claude, Gemini 같은 대규모 언어 모델(large language model, LLM)이 인기다보니, 일상적으로 LLM에게 분석이나 뭔가 태스크를 시키기 위해 자료를 건네는 것을 “학습시킨다”고 표현하는 경우가 많습니다. “내 자료를 Gemini에게 줘서 학습시켰다”처럼요. 하지만 엄밀히 말하면 이것은 학습이 아닙니다. 이런 LLM들은 이미 방대한 데이터로 “과거의 패턴을 알고리즘으로 만드는” 학습을 마친 상태입니다. 우리가 파일을 첨부하거나 질문을 입력하는 것은, 학습이 끝난 알고리즘에 입력값을 넣어 결과를 받아 보는 것에 가깝습니다. 함수 \(f\)를 새로 만드는 것이 아니라, 이미 만들어진 \(f\)에 \(x\)를 넣어 \(f(x)\)를 계산하는 것이지요. 그래서 대화가 끝나면 모델 자체는 그대로이고, 우리가 건넨 자료 때문에 모델이 바뀌지는 않습니다.

여튼 데이터 애널리틱스를 제대로 이해하고 연구하려면 데이터 분석만큼, 경우에 따라서는 그 이상으로 많은 수학이 필요합니다. 반면 이미 만들어진 애널리틱스의 결과물을 실제 문제에 적용하는 데에는 그렇게까지 많은 수학이 필요하지 않고, 오히려 그것을 구현하는 컴퓨터 공학적 역량이 더 중요해집니다. 데이터 엔지니어링이 컴퓨터 공학 쪽 끝에, 데이터 분석이 수학 쪽 끝에 있다면, 데이터 애널리틱스는 그 중간 어딘가에 있는 셈입니다. 그래서 컴퓨터 공학이나 수학의 세부 전공이 아닌 독립된 데이터 사이언스 전공의 교과 과정은 대개 데이터 애널리틱스를 기본으로 짜여 있습니다. 수학과 컴퓨터 공학을 균형 있게 공부하기에 좋기 때문입니다. 물론 그것은 기본값일 뿐이고, 엔지니어링이나 분석에 관심이 있는 학생은 그쪽 과목을 더 골라 듣는 식으로 공부할 수 있도록 되어있는 경우가 많습니다.

이 과목에서 다루는 갈래

데이터 사이언스 개론에서는 이 가운데 데이터 분석을 중심으로, 데이터 애널리틱스를 조금 곁들여 다룹니다. 위에서 보신 것처럼 데이터 분석을 제대로 하려면 사전 지식이 꽤 많이 필요하지만, 그것은 “제대로” 할 때의 이야기입니다. 문제 상황을 충분히 단순화하면 간단한 수학만으로도 맛보기는 충분히 가능합니다. 그래서 이 과목에서는 별다른 사전 지식 없이도 다룰 수 있는 간단한 경우들만 다룹니다.

데이터 엔지니어링은 꽤 깊은 컴퓨터 공학 이야기가 나오고 맛보기로 다루기도 어려워서, 본격적인 데이터 엔지니어링 대신 뒤에서 데이터 사이언스 인프라에 관한 간단한 이야기만 하겠습니다.

데이터 분석의 다섯 단계

그럼 이 과목의 중심인 데이터 분석이 대략 어떻게 진행되는지 조금 더 살펴보겠습니다.

데이터 분석은 이미 일어난 일의 데이터를 가지고 그 현상의 원인을 찾아내는 것을 목표로 합니다. 데이터 사이언스의 여러 갈래 가운데 전통적인 통계학과 가장 비슷한 철학을 가진 분야입니다. 데이터 분석가는 지금 분석하는 것이 어떤 문제 상황이고 우리가 어떤 의문을 품고 있는지를 정리하는 데서 출발해, 대략 다음 다섯 단계로 분석을 진행합니다.1

  1. 질문 설정과 구체화(stating and refining the question): 데이터로부터 무엇을 알아내고 싶은지, 해결할 문제가 무엇인지를 명확하게 정합니다.
  2. 데이터 탐색(exploring the data): 본격적인 분석에 앞서, 빠진 값이나 이상한 값은 없는지, 데이터가 전체적으로 어떻게 생겼는지를 훑어봅니다. 이 과정을 탐색적 자료 분석(exploratory data analysis, EDA)이라고도 부릅니다.
  3. 형식 모델 구성(building formal statistical models): 탐색 결과를 바탕으로 수학과 확률, 통계를 이용해 모델을 세우고, 통계적 검정이나 머신러닝 알고리즘 등으로 패턴을 찾고 가설을 검증합니다.
  4. 결과 해석(interpreting the results): 모델이 내놓은 결과가 처음에 세운 질문에 비추어 현실에서 어떤 의미를 갖는지 해석합니다.
  5. 커뮤니케이션(communicating the results): 해석한 결과를 다른 사람도 이해할 수 있도록 보고서, 시각화 자료, 발표 등으로 전달합니다.

듣고 보면 아주 당연한 과정입니다. 데이터 분석가는 이 다섯 단계를 끊임없이 되풀이하는 일로 먹고산다고 해도 과언이 아니고, 데이터 분석을 연구하는 사람들은 각 단계에서 쓸 수 있는 명제와 도구를 계속해서 만들어 냅니다.

다만 이 순서는 유명한 교재에서 정리한 것을 그대로 옮긴 것이고, 외우는 것 자체에는 큰 의미가 없습니다. 실제 실무나 연구에서는 이 순서를 그대로 밟기보다 닥치는 대로 해 나가는 경우가 대부분입니다. 그 “닥치는 대로”에도 어느 정도의 단계와 틀이 있고, 위의 다섯 단계는 그것을 일반화해 정리한 것일 뿐입니다.

기대하고, 확인하고, 고치기

그런데 이 다섯 단계가 1번부터 5번까지 한 번에 쭉 이어지는 것은 아닙니다. 각 단계 안에서는 항상 다음 세 가지 작은 과정이 반복됩니다.

  1. 기대치 설정: “데이터가 대략 이런 모습일 것이다”라는 사전 기대나 가설을 세웁니다.
  2. 데이터와 기대치 비교: 실제 데이터를 모아 기대치와 비슷한지 확인합니다.
  3. 기대치 수정 또는 데이터 조정: 기대가 틀렸다면 기대를 고치고, 데이터에 문제가 있다면 데이터를 바로잡습니다.

우리는 데이터가 현상을 설명해 줄 것이라는 기대를 품고 분석을 시작하므로, 데이터에 대해 늘 어떤 기대를 갖고 있습니다. 그리고 다섯 단계 하나하나를 진행하는 동안 이 기대를 끊임없이 세우고, 확인하고, 고쳐 나갑니다. 큰 바퀴 안에서 작은 톱니바퀴가 돌며 전체를 굴러가게 하는 모습을 떠올리시면 됩니다. 이렇게 데이터 분석은 한 방향으로 곧게 뻗은 길이 아니라, 끊임없이 기대하고 확인하고 궤도를 수정해 나가는 유기적이고 반복적인 과정입니다.

이제 다섯 단계 각각에서 무엇을 고려해야 하는지 하나씩 살펴보겠습니다.

1단계: 질문 설정과 구체화

질문을 세우고 구체화하는 단계는 데이터 분석의 가장 근본이 되는 단계입니다. 데이터 분석의 목적은 결국 데이터를 통해 우리의 질문에 대한 답을 찾는 것이니까요. 그렇다면 어떤 질문이 좋은 질문일까요? 이에 답하려면 먼저 우리가 던지는 질문이 어떤 성격을 갖는지부터 알아야 합니다. 데이터로 던질 수 있는 질문은 대략 다음 여섯 가지로 나뉩니다.2 작은 가게를 운영한다고 생각하고 예를 들어 보겠습니다.

질문의 유형 예시 무엇을 하는가
기술적(descriptive) 질문 “우리 가게의 하루 평균 매출은 얼마인가?” 가진 데이터를 요약합니다.
탐색적(exploratory) 질문 “매출이 많았던 날들에 공통점이 있는가?” 데이터에서 패턴을 찾아 새로운 가설을 만듭니다.
추론적(inferential) 질문 “이번 달 손님들에게서 보인 특징이 우리 가게 손님 전체에도 해당하는가?” 가진 데이터에서 본 패턴이 데이터 밖에서도 성립하는지 따집니다.
예측적(predictive) 질문 “다음 달 매출은 얼마일까?” 어떤 값들로 다른 값을 예측합니다. 왜 그렇게 되는지보다 예측이 얼마나 정확한지가 중요합니다.
인과적(causal) 질문 “블로그 홍보를 하면 매출이 오르는가?” 한 요인을 바꿨을 때 다른 값이 평균적으로 어떻게 변하는지 밝힙니다.
기계적(mechanistic) 질문 “블로그 홍보는 정확히 어떤 경로를 거쳐 손님의 방문으로 이어지는가?” 원인이 결과를 만들어 내는 세밀한 작동 원리를 파헤칩니다. 일반적으로 답하기가 매우 어렵습니다.

질문의 유형에 따라 답하는 데 쓰는 도구와 수학적 모델이 달라집니다. 그래서 지금 던지는 질문이 어떤 성격인지를 분명히 해야 합니다. 지금 하고 싶은 것이 예측인지, 추론인지를 명확히 정해야 알고자 하는 것이 무엇인지가 확실해지고, 그에 맞는 방법으로 답할 수 있습니다.

실제로 데이터 분석에서 가장 흔한 실수 가운데 하나가 바로 질문의 유형을 혼동하는 것입니다.3 대표적인 예가 추론적 질문의 답을 인과적 질문의 답처럼 받아들이는 경우입니다. “홍보를 많이 한 달에 매출이 높았다”는 것은 두 값이 함께 움직인다는 관찰일 뿐인데, 이를 “홍보가 매출을 올렸다”는 인과로 읽어 버리는 것이지요. 연말처럼 원래 손님이 많은 시기에 홍보도 많이 했다면, 매출을 올린 것은 홍보가 아니라 연말이었기 떄문이었을 수도 있습니다. 흔히 말하는 “상관관계는 인과관계가 아니다”가 바로 이 이야기입니다.

질문의 성격 말고도 좋은 질문이 갖춰야 할 조건이 몇 가지 더 있습니다.4

  • 결과를 들을 사람들이 관심을 가질 만한 질문이어야 합니다.
  • 아직 답이 나오지 않은 질문이어야 합니다. 재검증처럼 특별한 경우가 아니라면, 이미 답이 있는 질문을 다시 묻는 것은 의미가 없습니다.
  • 말이 되는 질문이어야 합니다. 그럴듯한 근거나 틀 위에서 나온 질문이어야 한다는 뜻입니다.
  • 답할 수 있는 질문이어야 합니다.
  • 너무 모호하지 않고 구체적이어야 합니다.

모두 당연한 이야기입니다. 정리하면, 잘 세운 질문이란 우리가 얻고자 하는 결과를 최대한 정확하게 얻어 낼 수 있는 성격으로 세워져 있고, 우리가 처한 문제의 해결책을 잘 대변하는 질문이라고 할 수 있습니다.

앞으로 이 과목에서도 문제 상황을 보고 질문을 세우는 과정이 자연스럽게 등장합니다. 물론 그때마다 “이 질문은 어떤 유형이고 왜 좋은 질문인가”를 일일이 따지지는 않고, 문제 상황에 맞는 질문을 직관적으로 세워 해결하는 식으로 진행하겠습니다.

질문을 세운 뒤에도 생각할 것은 남아 있습니다. 답이 어떤 형태가 될지, 그 질문에 답할 수 있는 데이터를 실제로 갖고 있는지, 가진 데이터가 한쪽으로 치우쳐 있어서 일반적인 답을 내기 어렵지는 않은지 등을 따져 봐야 합니다. 이 고민은 자연스럽게 다음 단계인 데이터 탐색으로 이어집니다.

2단계: 데이터 탐색

데이터 탐색은 가진 데이터를 말 그대로 탐색해서, 데이터가 전체적으로 어떤 구조를 갖는지 파악하는 과정입니다. 물론 데이터를 멍하니 쳐다본다고 답이 나오지는 않습니다. 데이터 탐색에는 크게 세 가지 목표가 있습니다.5

  • 데이터셋에 문제가 없는지 확인한다.
  • 이 데이터셋으로 우리가 세운 질문에 답할 수 있는지 확인한다.
  • 질문에 대한 답을 간단하게 스케치한다. 일종의 답의 시제품을 만들어 보는 것입니다.

먼저 데이터셋의 건강 상태를 점검합니다. 예를 들어 나이가 200살인 사람처럼 말이 안 되는 값이나, 비어 있는 값은 없는지 살펴봅니다. 간단한 예로, 어느 쇼핑몰의 고객 데이터를 판다스로 읽어서 요약해 보겠습니다.

import io
import pandas as pd

csv_text = """고객번호,나이,성별,월구매액
1,34,F,52000
2,27,M,31000
3,200,F,45000
4,41,,38000
5,,M,61000
6,29,F,-12000
7,38,M,47000
"""

df = pd.read_csv(io.StringIO(csv_text))
print(df[["나이", "월구매액"]].describe().round(1))
print()
print(df.isna().sum())
          나이     월구매액
count    6.0      7.0
mean    61.5  37428.6
std     68.1  23810.8
min     27.0 -12000.0
25%     30.2  34500.0
50%     36.0  45000.0
75%     40.2  49500.0
max    200.0  61000.0

고객번호    0
나이      1
성별      1
월구매액    0
dtype: int64

요약표 몇 줄만 봐도 이상한 점이 여럿 보입니다. 나이의 최댓값(max)이 200이고, 그 때문에 평균 나이(mean)가 61.5세로 중앙값(50%) 36세보다 훨씬 크게 나왔습니다. 월 구매액의 최솟값(min)은 음수인데, 환불이 섞여 들어왔을 수도 있고 단순한 입력 실수일 수도 있습니다. 아래쪽 표를 보면 나이와 성별이 비어 있는 고객도 한 명씩 있습니다. 이 상태로 바로 “우리 고객의 평균 나이는 61.5세”라고 결론을 냈다면 엉뚱한 분석이 되었을 것입니다. 우리는 이렇게 데이터를 직접 살펴보는 과정을 통해서 데이터가 정상적인지를 우선 검사해야합니다.

데이터가 건강하다면, 그다음에는 이 데이터로 질문에 답할 수 있는지를 확인합니다. 연령대별로 어떤 상품이 잘 팔리는지 분석하고 싶은데 데이터에 나이 정보가 없다면 곤란하겠지요. 답할 수 없다면 데이터를 새로 구하거나, 질문을 새로 세워야 합니다.

여기까지 문제가 없다면, “대략 이런 결과가 나오겠구나” 하는 답의 스케치를 그려 봅니다. 앞에서 말한 기대치가 여기서 처음으로 구체적인 모습을 갖추게 됩니다. 이제 이 스케치를 정확하게 다듬기 위해 다음 단계로 넘어갑니다.

3단계: 형식 모델 구성

이 시점에서 우리는 데이터의 구조를 아주 대략적으로 파악한 상태입니다. 이것을 더 정확하게 파악하기 위해 모델을 세웁니다. 여기서 말하는 모델, 정확히는 형식 모델(formal model)이란 데이터를 논리적으로 설명하기 위한 수학이나 통계의 도구를 말합니다. 대개 함수의 형태를 띱니다.

모델은 왜 필요할까요?

애초에 모델을 왜 만들어야 할까요? 첫 번째 이유는 모델이 데이터의 구조를 단순화해 준다는 것입니다. 데이터 하나에는 적게는 수십, 많게는 수백 개의 변수가 들어 있습니다. 모델 없이 이 모든 것을 날것 그대로 고려해서 결론을 내기란 쉽지 않습니다. 그래서 질문에 답하는 데 필요한 부분만 남기고 데이터를 올바르게 단순화해 주는 모델을 고르는 것입니다.

두 번째 이유는 모델이 수학적으로 정확하게 정의되어 있어서, 우리가 아는 수학과 통계 지식으로 모델의 성질을 분석하고 그것을 통해 현상을 해석할 수 있다는 것입니다. 예를 들어 “광고를 많이 할수록 매출이 오른다”는 명제를 따져 보고 싶다면, 알맞은 모델을 하나 골라 광고비에 대한 매출의 변화율을 분석하는 식으로 매출이 얼마나 오르는지 파악할 수 있습니다. (물론 복잡한 문제로 가면 이렇게 단순하게 해석되지 않는 경우도 많습니다.)

앞에서 모델을 “수학이나 통계의 도구”라고 했는데, 정확히는 두 가지를 동시에 쓴다고 보시면 됩니다. 모델의 뼈대는 수학이 만들고, 그 뼈대에 들어가는 각 구성 요소에는 통계적 모델을 끼워 넣습니다. 데이터가 보여 주는 현상은 정확하게 결정되어 있지 않고 언제나 불확실성이 있기 때문에, 확률변수 같은 통계의 도구로 그 불확실성까지 담아낸 모델을 만드는 것입니다.

이렇게 만든 모델로 우리는 미래를 예측하거나, 직접 관측할 수 없는 값을 추정하는 등 데이터가 말해 주는 무언가를 끌어냅니다. 모델은 결국 “이 데이터가 현실에서 어떤 과정을 거쳐 만들어졌을까”에 대한 우리의 기대를 합리적이고 논리적으로 표현한 것입니다. 그래서 모델을 세우는 단계에서도 앞에서 말한 기대치를 세우고, 확인하고, 고치는 과정을 계속 거치게 됩니다.

좋은 모델은 덜 틀린 모델입니다

모델이 왜 필요한지는 알았으니, 이제 어떤 모델을 골라야 하는지가 궁금해집니다. 당연히 좋은 모델을 골라야 할 텐데, 좋은 모델이란 무엇일까요? 한마디로 하면 최대한 덜 틀린 모델입니다.

모델은 데이터 뒤에 있는 실제 이치를 있는 그대로 표현하지 못합니다. 현실 세계를 수학과 논리의 언어로 100% 옮겨 적는 것은 불가능하니까요. 통계학자 박스(G. E. P. Box)는 이를 두고, 모든 모델은 틀렸지만 그중 일부는 쓸모가 있다는 유명한 말을 남겼습니다.6 그래서 우리는 모델이 어느 정도 틀린다는 것을 받아들이고, 그 틀림이 최소가 되는 모델을 골라야 합니다. 그러면서도 질문에 답할 수 있는 모델 가운데 가장 단순한 모델을 고르는 것이 가장 좋다고 여겨집니다.

모수와 학습

모델의 종류를 골랐다면, 그 모델이 구체적으로 어떤 모양인지 정해야 합니다. 예를 들어 통계에서 자주 쓰는 정규분포를 생각해 보겠습니다. 데이터가 정규분포를 따른다고 정했더라도, 그것이 정확히 어떤 정규분포인지, 즉 정규분포의 모양을 결정하는 평균과 분산이 얼마인지를 정해야 합니다. 이렇게 모델의 구체적인 모양을 결정하는 값을 모수(parameter) 또는 파라미터라고 합니다.

모수를 정하기 위해 모델에 데이터를 넣는 과정을 데이터 사이언스에서는 학습(training) 또는 피팅(fitting)이라고 부릅니다. 이름은 거창하지만 대단한 개념은 아닙니다. 데이터를 넣고, 그 데이터를 바탕으로 모델의 모수를 계속 고쳐 나가는 과정을 말합니다. 통계학에서는 같은 일을 모수 추정(parameter estimation)이라고 부릅니다. 이처럼 통계학과 데이터 사이언스에서는 같은 개념을 다른 이름으로 부르는 경우가 많습니다. 데이터로부터 모수를 어떻게 정하는지는 기초 통계학(추가 예정)에서 간단하게 소개되며, 수리적 데이터 분석과 통계적 추론의 최대우도 추정에서 좀 더 정확하게 다뤄집니다.

모델이 제대로 작동하는지 확인하기

모델을 고르고 구현하는 일도 앞에서 말한 톱니바퀴처럼 반복되는 과정입니다. 먼저 모델이 어떤 결과를 낼지, 무엇을 할 수 있고 무엇을 할 수 없는지에 대한 기대치를 세우고, 프로그래밍 등으로 모델을 구현합니다. 그런 다음 모델이 제대로 작동하는지 몇 가지 방법으로 확인합니다.

첫째는 토이 데이터(toy data)로 시험해 보는 것입니다. 토이 데이터란 우리가 정답을 이미 알고 있어서 결과를 확신할 수 있는 데이터를 말합니다. 정답을 아는 데이터를 넣었는데도 모델이 엉뚱한 답을 낸다면, 모델 자체에 문제가 있는 것입니다.

둘째는 모델을 학습시킬 때 쓰지 않은 데이터로 성능을 확인하는 것입니다. 그래서 보통 데이터를 학습용 데이터(training data)와 테스트용 데이터(test data)로 나누고, 학습에 쓴 데이터는 평가에 쓰지 않는 것을 원칙으로 합니다. 학습에 쓴 데이터로 평가하면, 시험 문제를 미리 보고 시험을 치르는 것과 같아서 성능이 실제보다 좋아 보이기 때문입니다. (데이터가 너무 적어서 이렇게 나누기 어려울 때 쓸 수 있는 교차 검증(cross-validation) 같은 방법도 있습니다.)

셋째는 일부러 데이터를 망가뜨려 넣어 보는 것입니다. 데이터를 망가뜨린다는 것은 데이터의 핵심적인 정보를 고의로 뭉개 버린다는 뜻입니다. 이렇게 망가진 데이터를 넣었는데도 모델이 신기할 만큼 정확한 답을 낸다면, 그 모델은 좋은 모델이 아니라 어디선가 정답을 몰래 베껴 내고 있는 모델일 가능성이 높습니다.

세 가지를 간단한 직선 모델로 모두 해 보겠습니다. 정답이 절편 1, 기울기 2인 직선 위에 작은 잡음을 섞은 토이 데이터를 만들고, 최소제곱법으로 직선을 맞춰 봅니다.

import numpy as np

np.random.seed(2026)

# 1) 토이 데이터: 정답(절편 1, 기울기 2)을 알고 있는 데이터
x = np.random.rand(200)
y = 1 + 2 * x + 0.1 * np.random.randn(200)
slope, intercept = np.polyfit(x, y, 1)
print(f"토이 데이터  : 절편 = {intercept:.3f}, 기울기 = {slope:.3f}")

# 2) 학습용과 테스트용으로 나누기
idx = np.random.permutation(200)
train, test = idx[:150], idx[150:]
slope, intercept = np.polyfit(x[train], y[train], 1)
mse = np.mean((y[test] - (intercept + slope * x[test])) ** 2)
print(f"테스트 오차  : {mse:.4f}")

# 3) 일부러 망가뜨린 데이터: y를 무작위로 섞어 x와의 관계를 끊기
y_broken = np.random.permutation(y)
slope, intercept = np.polyfit(x, y_broken, 1)
print(f"망가진 데이터: 절편 = {intercept:.3f}, 기울기 = {slope:.3f}")
토이 데이터  : 절편 = 1.013, 기울기 = 1.985
테스트 오차  : 0.0101
망가진 데이터: 절편 = 1.991, 기울기 = 0.075

첫 줄에서 모델은 정답인 절편 1, 기울기 2에 아주 가까운 값을 찾아냈습니다. 둘째 줄의 테스트 오차(예측값과 실제값 차이의 제곱 평균)는 약 \(0.01\)인데, 이것은 우리가 일부러 섞은 잡음의 크기(\(0.1^2 = 0.01\))와 거의 같습니다. 학습에 쓰지 않은 데이터에서도 모델이 잡음 말고는 놓친 것이 없다는 뜻입니다. 마지막 줄에서는 \(y\)를 무작위로 섞어 \(x\)와의 관계를 끊어 버렸더니, 기울기가 거의 0으로 떨어졌습니다. 관계가 없는 데이터에서 관계를 찾지 못하는 것이 정상입니다. 만약 여기서도 기울기가 여전히 2 근처로 나왔다면, 어딘가에서 정답이 새어 들어가고 있다는 신호로 보고 코드를 의심해야 합니다.

이런 확인을 거쳐 결과가 나오면, 이제 그 결과를 해석할 차례입니다.

4단계: 결과 해석

결과 해석 단계는 생각보다 간단합니다. 사실 가장 까다로운 부분은 모델이 잘 작동하는지까지 판단해야 하는 앞의 모델 단계입니다.

결과 해석 단계에서는 처음에 세웠던 질문을 다시 떠올려 그에 대한 답을 만들고, 결과의 방향과 크기, 그리고 그 결과가 얼마나 불확실한지를 해석합니다. 우리의 결과를 이미 알려진 다른 결과들과 나란히 놓고 비교해 보기도 하고, 반대로 “이 결과가 틀렸다면 왜 이런 결과가 나왔을까?”를 따져 보며 해석하기도 합니다. 마지막으로 이 모든 해석을 종합해, 질문의 답으로서 현실에서 어떤 조치를 취해야 할지를 결정합니다.

그런데 알고리즘 자체가 핵심 사업인 테크 기업이나 AI 기업이 아니라면, 데이터 사이언티스트 본인이 최종 결정권자인 경우는 드뭅니다. 설령 결정권자라 하더라도, 회사의 주주처럼 데이터 사이언스를 잘 모르는 사람들에게 분석 결과를 그대로 건네며 “알아서 이해하세요”라고 할 수는 없습니다. 그래서 분석 결과를 결정권자와 이해관계자에게 설명하는 마지막 단계가 필요합니다.

5단계: 커뮤니케이션

커뮤니케이션의 방법은 우리 모두가 이미 잘 알고 있습니다. 결국 말하기가 가장 중요합니다. 청중 앞에서 자신의 결과를 잘 설명하고, 청중의 질문에 적절히 답할 수 있어야 합니다.

결과를 설명할 때는 데이터 시각화가 큰 도움이 됩니다. 그래프를 그리는 것 자체는 어렵지 않지만, 지금 설명하는 맥락에서 “정확히 핵심을 짚었다”는 평가를 받을 만한 시각 자료를 고르는 안목이 필요합니다. 더 자세한 내용을 원하는 청중을 위해 보고서를 잘 써 두는 것도 중요합니다.

효과적으로 전달하려면 다음과 같은 점을 생각해 봐야 합니다.

  • 청중이 누구인가? 기술적인 배경이 없는 청중이라면 전문 용어는 최대한 빼는 것이 좋습니다.
  • 어떤 질문과 반응이 나올까? 예상되는 질문을 미리 생각해 두면 훨씬 매끄럽게 답할 수 있습니다.
  • 청중이 이해하기에 충분한 정보를 주고 있는가? 너무 적어도, 너무 많아도 전달이 어렵습니다.

이런 이유로 요즘 새로 생기는 데이터 사이언스 전공은 물론이고 수학 전공에서도, 전통적인 강의와 세미나, 실습을 넘어 수학이나 데이터 사이언스를 대중에게 잘 설명하는 법, 그리고 이 학문들이 사회와 어떻게 상호작용하는지 이해하는 법 같은 이른바 소프트 스킬(soft skill)을 다루는 수업을 교과 과정에 넣는 추세입니다.

정리

  • 데이터 사이언스는 흔히 데이터 엔지니어링(기반), 데이터 분석(왜 일어났는가), 데이터 애널리틱스(무엇이 일어날 것인가)의 세 갈래로 나뉩니다. 데이터 사이언스 개론은 이 가운데 데이터 분석을 중심으로 다룹니다.
  • 데이터 분석은 질문 설정, 데이터 탐색, 모델 구성, 결과 해석, 커뮤니케이션의 다섯 단계로 정리할 수 있고, 각 단계 안에서는 기대치를 세우고, 확인하고, 고치는 과정이 끊임없이 반복됩니다.
  • 질문은 유형(기술·탐색·추론·예측·인과·기계)에 따라 쓰는 도구가 달라지므로, 지금 던지는 질문이 어떤 유형인지 분명히 해야 합니다.
  • 모델은 언제나 어느 정도 틀리기 때문에, 질문에 답할 수 있으면서 가장 덜 틀리고 단순한 모델을 고르고, 토이 데이터·테스트 데이터·망가뜨린 데이터 등으로 제대로 작동하는지 확인합니다.

그런데 이 모든 과정은 한 가지 전제 위에 서 있습니다. 바로 데이터 자체가 믿을 만하다는 것입니다. 아무리 정교한 모델과 꼼꼼한 확인을 거쳐도, 애초에 데이터가 잘못 모였다면 어떻게 될까요? 다음 글에서는 데이터가 어디서 어떻게 왔는지가 왜 중요한지 살펴보겠습니다.
